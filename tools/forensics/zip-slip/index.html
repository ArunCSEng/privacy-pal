What is Zip Slip (CWE-22)?

Zip Slip is a critical arbitrary file overwrite vulnerability that occurs when unpacking archives containing filenames structured with directory traversal paths (e.g., ../../../../etc/shadow or ..\..\..\Windows\System32\cmd.exe). If an unpacking library concatenates the destination directory directly with the archived entry's name without enforcing canonical boundary verification, the extractor writes files outside the targeted directory.

Common Threat Vectors Detected

  • Relative Traversal Sequences: Encounters with ../, ..\, or terminal /.. designed to step up and escape destination boundaries.
  • Absolute & Drive-Root Overwrites: Entries prefixed with root indicators like /etc/, Windows drive indicators like C:\, single leading backslashes (\Windows\...), or UNC network shares (\\server\share).
  • Windows Drive-Relative Bypasses: Paths formatted as C:payload.exe without leading slashes.
  • NTFS Alternate Data Streams (ADS): Hidden executable or data stream injections using colon syntax (file:stream or ::$DATA).
  • Unicode Homoglyphs & Obfuscation: Full-width characters (\uFF0F, \uFF0E) and multi-pass URL encodings (..%2f, %252e).
  • Null Byte Injection: Entries embedding \0 or %00 byte characters to evade legacy string terminators.
  • DOS / Windows Reserved Device Names: Entries named CON, PRN, AUX, NUL, COM1-9, or LPT1-9 that trigger operating system locks.

Safe Extraction Implementation Pattern

When extracting archive payloads in backend workflows, verify that the canonical destination path of the extracted entry strictly begins with the intended root directory path:

  • Python: Ensure os.path.commonpath([target_dir, resolved_path]) == target_dir before writing.
  • Java: Ensure file.toPath().normalize().startsWith(destDirectory.toPath()).
  • Node.js: Ensure path.resolve(destDir, entryName).startsWith(path.resolve(destDir) + path.sep).
