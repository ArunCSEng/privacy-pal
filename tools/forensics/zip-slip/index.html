What Zip Slip Is

Extracting an archive should write its files inside the folder you chose. Zip Slip (a form of CWE-22 path traversal) breaks that assumption: an entry's stored name is something like ../../../../etc/cron.d/evil, and an extractor that simply joins the destination folder with that name follows the ../ steps up and out, writing the file somewhere else on the system. Depending on where it lands, that can mean overwriting a scheduled task, an SSH authorized_keys, a web file or a binary — a path to code execution. The flaw is in the extractor, not the format, and it affects any ZIP-based file.

What This Tool Does

This scanner lets you check an archive's entry names before you extract it. Drop in a .zip (or a JAR, WAR, APK or Office file — all ZIP archives), and it reads the archive's index and lists every entry, flagging any whose path looks like it would escape the extraction folder. It reads the file in your browser and uploads nothing, so it is safe to use on archives you do not yet trust.

How to Use the Tool

  1. Open an archive — drag in a .zip, or any of the ZIP-based formats: .jar, .war, .apk, or an Office file such as .docx or .xlsx. Only the Central Directory is read, so nothing is decompressed or written to disk.
  2. Check the threat count first — a non-zero count means at least one entry's stored path would escape the folder you extract into. That is the answer you came for, before running unzip.
  3. Review the entry table — each row shows the Entry Path in Archive exactly as stored, a Security Status, and Classification / Risk Details naming which pattern triggered: a ../ traversal, an absolute path, a backslash, an encoded sequence, or an NTFS stream colon.
  4. Judge the flagged paths yourself — look at the stored path rather than the filename alone. A path that resolves outside the destination is the problem, regardless of how harmless the final filename looks.
  5. Keep a record — Export Forensic Report saves the full entry list with the findings, and Clear & New Scan resets for the next archive.

If you must extract a flagged archive, do it in a throwaway container or VM, and use an extractor that resolves each path and refuses anything landing outside the target directory.

How It Reads the Archive

A ZIP file keeps its index — the Central Directory — near the end, pointed to by an End of Central Directory (EOCD) record. The tool scans backwards for the EOCD signature (50 4B 05 06) and verifies it points at a real Central Directory before trusting it, which avoids being fooled by that byte pattern appearing inside file data. It also recognises ZIP64 (the 50 4B 06 07 locator and 50 4B 06 06 record) so large archives with 64-bit offsets are read correctly. It then walks each Central Directory entry (50 4B 01 02) and reads the stored file name — without decompressing anything.

What It Flags

For each entry name the tool normalises the path the way an extractor would and checks for the patterns that let a file escape:

  • Directory traversal — ../ sequences that climb out of the destination, including ones that only appear after normalising.
  • Absolute paths — a leading / (or a drive letter) that ignores the destination entirely.
  • Backslashes — ..\, which traverse on Windows and can slip past checks that only look for forward slashes.
  • Encoded sequences — %2e, %2f, %5c and the like, which defeat filters that check before decoding.
  • NTFS stream names — a colon in the name (the file:stream alternate-data-stream syntax).

Flagged entries are counted and highlighted, with a SHA-256 of the archive and a JSON report you can save.

A Worked Example You Can Reproduce

You can build a malicious archive to see the flagging work. In Python: 

import zipfile
with zipfile.ZipFile("evil.zip", "w") as z:
    z.writestr("readme.txt", "harmless")
    z.writestr("../../../../tmp/evil", "payload")

Open evil.zip here and the entry list shows readme.txt as clean and ../../../../tmp/evil flagged as a path-traversal risk, with the threat count at one. A normal archive with only in-folder names lists every entry clean. Either way the SHA-256 in the summary matches sha256sum evil.zip, confirming the tool read the same bytes.

How to Extract Safely

The fix is the same in every language: before writing an entry, resolve the full absolute path of the target and confirm it still begins with the destination folder's path plus a separator, decoding and normalising the name first. For example, in Python: 

import os, zipfile

def safe_extract(zip_path, dest):
    dest = os.path.realpath(dest) + os.sep
    with zipfile.ZipFile(zip_path) as z:
        for name in z.namelist():
            target = os.path.realpath(os.path.join(dest, name))
            if not target.startswith(dest):
                raise ValueError(f"Blocked traversal entry: {name}")
            z.extract(name, dest)

Most current libraries do this for you, but custom extraction code frequently does not — which is where this scanner helps.

Frequently Asked Questions

What is Zip Slip?
Zip Slip (a form of CWE-22 path traversal) is when an archive entry's stored name points outside the folder it is being extracted into — using ../ sequences or an absolute path. An extractor that joins the destination folder with that name without checking can write the file elsewhere, overwriting things like cron jobs, SSH keys or web files. This scanner flags such entries before you extract.
Are DOCX, JAR, WAR and APK files ZIP archives?
Yes. Office documents (DOCX, XLSX, PPTX), Java packages (JAR, WAR) and Android apps (APK) are all ZIP archives under the hood, so they can carry the same traversal entries. Any application that unzips one to read its contents is exposed to Zip Slip if it does not validate paths, so this tool scans them the same way it scans a plain ZIP.
How do I extract an archive safely?
Before writing each entry, resolve the full absolute path of the intended destination and confirm it still begins with the extraction folder's path plus a separator; refuse any entry that does not. Decode and normalise the name before checking, not after, and reject absolute paths and backslashes. Most up-to-date libraries do this, but custom extraction code often does not.
Does a clean result mean the archive is completely safe?
No. This scanner reads the stored paths in the Central Directory and flags traversal, absolute, backslash, encoded and NTFS-stream patterns, which catches the common cases. It does not resolve symlink entries, model every parser-specific quirk, or judge the file contents. Treat a clean result as one good check, and still extract untrusted archives in an isolated sandbox.
Is my archive uploaded anywhere?
No. The file is read into memory in your browser, and the Central Directory parsing, the path checks, the SHA-256 hash and the JSON export all run there. Nothing you open is sent to a server; the page makes no network request for your archive.
