How the Browser-Native PCAP Parser Operates

Standard network traffic captures produced by tools like tcpdump, dumpcap, or Snort follow the classic libpcap file specification. BitDark reads the raw byte stream directly via the HTML5 FileReader and ArrayBuffer APIs, decoding structures without transmitting packets to remote servers:

  • Global Libpcap Header (24 Bytes): Evaluates the initial 32-bit magic number (0xA1B2C3D4 for microsecond precision or 0xA1B23C4D for nanosecond precision) to establish byte endianness, followed by snapshot length (snaplen) and data link type (Ethernet DLT_EN10MB).
  • Packet Header (16 Bytes): Decodes UNIX epoch timestamp seconds, fractional microsecond offsets, included capture length (incl_len), and raw wire length (orig_len).
  • Layer 2 / Ethernet II & 802.1Q: Extracts MAC addresses, checks for VLAN tags (`0x8100`), and determines the inner Layer 3 EtherType discriminator (0x0800 for IPv4, 0x86DD for IPv6, 0x0806 for ARP).
  • Layer 3 / Internet Protocol: Dynamically calculates IPv4 Internet Header Length (`IHL`), validates Total Length, extracts TTL, Protocol, and IP addresses. For IPv6, processes the 40-byte fixed header including Next Header and 128-bit addresses.
  • Layer 4 / Transport: Decodes source and destination ports, sequence numbers, acknowledgement numbers, and TCP control flags (SYN, ACK, FIN, RST, PSH, URG), along with common UDP port heuristics.
