Encoding Is Not Encryption

The one thing to be clear about: these are all reversible representations with no key and no secrecy. Base64 text isn't protected — anyone can paste it back and read it. Encoding changes how bytes are written, not who can read them. Never use it to hide passwords, tokens or personal data; if something needs to stay private, encrypt it.

The Formats, and Where You Meet Them

FormatAlphabet / formWhere it shows up
Base64A–Z a–z 0–9 + / with = paddingEmail attachments, data URIs, JSON blobs

Base58Bitcoin alphabet, no 0 O I lCrypto addresses and keys (avoids look-alike characters)
Base32A–Z 2–7 with = paddingTOTP 2FA secrets, case-insensitive IDs
HexBase16, two chars per byteHashes, keys, byte-level debugging
Binary8 bits per byteTeaching and low-level inspection

The differences are practical: Base64URL swaps the two Base64 characters that break URLs; Base58 drops the characters people misread when copying by hand; Base32 is case-insensitive and avoids digits that look like letters. Each exists to move binary safely through a particular channel.

A Worked Example You Can Reproduce

Enter the text Hello (UTF-8 mode) and you get: 

Base64     SGVsbG8=
Base64URL  SGVsbG8
Base58     9Ajdvzr
Base32     JBSWY3DP
Hex        48656c6c6f
Binary     01001000 01100101 01101100 01101100 01101111

These match standard library output exactly, and conversion is lossless both ways — paste 9Ajdvzr in Base58 mode or SGVsbG8= in Base64 mode and you get Hello back. The tool also handles multi-byte characters correctly: it encodes text as UTF-8 first, so an emoji or accented letter round-trips intact.

A Note on Size

Encoding never makes data smaller — it's not compression. Base64 is about 33% larger than the raw bytes, Hex is exactly twice the size, and Binary is eight times. That overhead is the price of representing arbitrary bytes in a limited, text-safe alphabet, which is why you encode only when a channel needs it.

Frequently Asked Questions

Is Base64 a form of encryption?
No. Base64 is an encoding — a reversible way to write bytes using text-safe characters, with no key and no secrecy. Anyone can decode it instantly. Use it to transport data, never to protect it; for privacy you need actual encryption.
What's the difference between Base64 and Base64URL?
They encode the same bytes but Base64URL replaces the + and / characters (which have special meaning in URLs) with - and _, and usually omits the = padding. Use Base64URL anywhere the value goes into a URL, filename or JWT; standard Base64 elsewhere.
Why does Base58 leave out some characters?
Base58 omits 0, O, I and l because they're easily confused when read or typed by hand. That's why it's used for cryptocurrency addresses and keys, where a single mis-copied character would send funds to the wrong place.
Which format should I use for a TOTP secret?
Base32. Authenticator secrets are shared as Base32 because it's case-insensitive and avoids ambiguous digits, making the secret easier to type or read from a QR code's text. This tool will convert a secret to or from Base32 for inspection.
Does encoding make my data bigger?
Yes. Encoding adds overhead rather than compressing: Base64 is roughly a third larger than the raw bytes, Hex is double, and Binary is eight times. You encode to make bytes safe for a text channel, accepting the size cost, not to save space.
