What This Tool Decompresses

This takes a compressed stream — pasted as Base64 or hex, or uploaded as a file — and expands it back to readable text or a hex dump. It handles the deflate family: gzip, zlib (also called deflate), and raw deflate, and can auto-detect which one you have from its header. It's for inspecting compressed payloads — a gzipped API response, a deflate stream pulled out of a PNG or PDF, a compressed cookie — directly in your browser.

The Three Formats, and How They Differ

FormatHeaderWhere you meet it
Gzip (RFC 1952)Starts 1f 8b; CRC32 + length trailer.gz files, HTTP Content-Encoding: gzip
Zlib / Deflate (RFC 1950)2-byte header (often 78 9c); Adler-32 trailerPNG and PDF streams, many network protocols
Raw Deflate (RFC 1951)No header or trailer — just the compressed bitsInside ZIP entries and formats that supply their own framing

All three use the same deflate compression at their core; they differ only in the wrapper. That's why "deflate" can be ambiguous — Auto-Detect reads the leading bytes (1f 8b for gzip, a valid zlib header otherwise) and falls back to raw deflate when there's no recognisable header.

What It Does Not Handle

Despite the broad name, this covers the deflate family only. It does not decompress Brotli, Zstandard (zstd), LZ4, bzip2, or xz/LZMA, and it doesn't extract archive containers like ZIP, 7z or TAR — those bundle multiple files and need an archive tool. If a payload won't decompress here and you're sure it's compressed, it's likely one of those other formats.

How It Works

Decompression uses the browser's built-in DecompressionStream, the same zlib-based engine the platform uses everywhere, so the output matches what gunzip or a zlib library would produce. Input can be Base64 (standard or URL-safe), hex, or raw binary; output can be shown as UTF-8 text or as a hex dump when the result is binary rather than text.

A Worked Example You Can Reproduce

Load the built-in Gzip sample (or paste any gzip stream as Base64). A gzip stream always begins with the bytes 1f 8b, and decompressing it returns the original text with the output size shown. In testing, a 216-byte text compressed to gzip and pasted back as Base64 decompresses to exactly those 216 bytes — whether you select Gzip explicitly or leave it on Auto-Detect, and the same holds for a zlib stream. That round trip, compressed in one place and expanded here to the identical bytes, is the check that the decoder is working to spec.

Compression Isn't Encryption

Worth noting: compressed data isn't protected. Anyone can decompress a gzip or deflate stream — there's no key involved — so compression shrinks data, it doesn't hide it. If a payload needs to stay private it must be encrypted, not merely compressed.

How to Use the Tool

  1. Choose file or text input, and set the input encoding (Base64, hex or raw binary) to match your data.
  2. Pick the algorithm, or leave it on Auto-Detect to let the header decide.
  3. Decompress, then view the result as text or a hex dump, with input/output sizes and the compression ratio.
  4. Download or copy the output if you need it elsewhere.

Scope and Limits

  • Deflate family only. No Brotli, zstd, LZ4, bzip2, xz, or archive extraction.
  • Output can be much larger than input. Compression ratios are high, so a small stream may expand into a very large result — view it as a hex dump if it isn't text.
  • Not decryption. Compressed data is readable by anyone; use encryption for secrecy.
  • Runs locally. Decompression happens in your browser — nothing is uploaded — so it's safe for private payloads.

Frequently Asked Questions

What's the difference between gzip, zlib and raw deflate?
They share the same deflate compression but wrap it differently. Gzip adds a 1f 8b header and a CRC32 trailer; zlib adds a short header and an Adler-32 checksum; raw deflate has neither. Auto-Detect reads the leading bytes to tell them apart and falls back to raw deflate when there's no header.
Why won't my Brotli or Zstandard data decompress?
This tool handles only the deflate family (gzip, zlib, raw deflate). Brotli, Zstandard, LZ4, bzip2 and xz are different algorithms it doesn't support, and ZIP or 7z are archive containers that need an extraction tool. If a valid stream fails here, it's probably one of those.
Which input encoding should I choose?
Match how you received the data. Use Base64 for a Base64 string (standard or URL-safe), Hex for a hex dump, and raw binary when uploading a file or pasting Latin-1 bytes. Picking the wrong encoding means the bytes are misread before decompression even starts.
Does decompressing protect or expose my data?
Neither in a security sense — compression isn't encryption. Anyone can decompress a gzip or deflate stream without a key. Here it also runs entirely in your browser and nothing is uploaded, so it's safe to inspect private payloads, but don't rely on compression to hide anything.
The output looks like garbage — what happened?
Usually the data decompressed fine but isn't text — switch the output to Hex Dump to inspect the bytes. If decompression itself failed, check that the input encoding matches the data and that the stream really is gzip, zlib or raw deflate rather than another format.
