How Regular Expression Denial of Service (ReDoS) Occurs

ReDoS arises when a Non-deterministic Finite Automaton (NFA) based regex engine encounters an input string designed to trigger exponential or high-order polynomial backtracking paths. When a pattern contains nested quantifiers, overlapping alternatives, or ambiguous group boundaries that fail near the tail end of an input, the evaluation engine systematically tests every possible permutation before concluding a non-match.

Common Vulnerable Pattern Archetypes

  • Nested Quantifiers: Patterns like (a+)+, (a*)*, or (x+x+)+y create O(2n) combinatorial explosions when fed repeated matching characters followed by an unexpected mismatch.
  • Overlapping Alternation with Repetition: Patterns such as (a|a)+ or (b|b+)+ force duplicate branches that double the verification stack with each input symbol.
  • Ambiguous Delimiters: Patterns like .*[a-z]+.* with loose boundary anchors can cause massive polynomial degradation on long, multi-line text blocks.

Isolated Sandboxed Execution

Standard in-thread regex tests can freeze or crash the browser UI thread if catastrophic backtracking occurs. BitDark encapsulates test executions inside isolated, dynamically allocated Web Workers. If an execution exceeds the watchdog threshold (2 seconds), the parent worker terminates the thread instantly, preventing tab lockups and returning vulnerability telemetry cleanly.
