What the Tool Does

This formats, validates and minifies JSON in your browser. Format pretty-prints valid JSON with your chosen indentation; Minify strips all whitespace for the smallest payload; and validation runs on every action, telling you whether the input is well-formed and, if not, where it broke. There's also a best-effort Repair that fixes common hand-editing mistakes. Nothing is uploaded — it all runs locally.

Validation Is Strict, by Design

Formatting and validation use the browser's own JSON parser, which follows the JSON standard (RFC 8259) exactly. That means it rejects things people often write by habit but which aren't valid JSON:

  • Trailing commas — {"a": 1,} is invalid.
  • Comments — // and /* */ aren't allowed in JSON.
  • Single quotes — strings and keys must use double quotes.
  • Unquoted keys — {name: "x"} must be {"name": "x"}.

That strictness is a feature: it catches exactly the mistakes that would make another system reject your JSON later.

The Repair Button: Useful, but Review the Result

Repair handles the three most common problems — removing trailing commas, converting single quotes to double, and quoting unquoted keys — then re-validates. For typical hand-written JSON it works well; for example: 

{name: 'Arun', age: 30, tags: ['a','b',],}
  → { "name": "Arun", "age": 30, "tags": ["a", "b"] }

Be aware of how it works, though: it applies text pattern-matching, not a full relaxed-JSON parser. That means it can misfire on a string value that happens to contain the patterns it looks for — a value like "total, cost: high" could have its inner text altered, because the repair can't always tell structure from content. So treat Repair as a fast first pass and always check the output before relying on it, rather than trusting it blindly on complex or untrusted input.

How to Use the Tool

  1. Paste your JSON and pick an indent width.
  2. Format to pretty-print, or Minify to compact; either way you'll see a valid/invalid status and the size change.
  3. If it's invalid, read the error, or try Repair for common mistakes — then review the repaired output.
  4. Copy the result when it's what you need.

Scope and Limits

  • Standard JSON only. It doesn't parse JSON5, JSONC (with comments) or other relaxed dialects — convert or repair those first.
  • Repair is heuristic. It fixes common errors but can alter string contents in edge cases; always check its output.
  • Formatting preserves data. Pretty-printing and minifying change only whitespace, never values.
  • Runs locally. Your JSON is processed in the browser — nothing is uploaded — so it's safe for private data.

Frequently Asked Questions

Why does my JSON with a trailing comma fail?
Trailing commas aren't valid JSON, even though many languages allow them. The validator follows the JSON standard strictly, so {"a": 1,} is rejected. Remove the comma, or use Repair, which strips trailing commas automatically.
Can it handle comments or single quotes?
Not as valid JSON — the standard forbids both. Repair will convert single quotes to double quotes and quote unquoted keys, but it doesn't strip comments. For a format that allows comments you'd need a JSON5 or JSONC parser, which is a different standard.
Is the Repair feature always safe to trust?
Use it, but review the result. Repair uses text pattern-matching to fix common mistakes, so on complex input it can occasionally alter the contents of a string value that resembles those patterns. It's a helpful first pass, not a guaranteed correct transformation.
Does formatting or minifying change my data?
No. Both only change whitespace — indentation and line breaks — not the values, keys or structure. Minified and formatted versions of the same JSON represent exactly the same data.
Is my JSON sent to a server?
No. Parsing, formatting, minifying and repair all run in your browser, so nothing you paste is uploaded. You can safely work with private or sensitive JSON.
