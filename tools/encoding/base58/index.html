What Base58 and Base62 Are For

Base58 and Base62 encode binary data as compact, copy-friendly text. Base58 deliberately drops the four characters people misread — 0, O, I and l — which is why cryptocurrency addresses, keys and IPFS identifiers use it: a hand-copied value is far less likely to be transcribed wrong. Base62 keeps all of 0–9 A–Z a–z for slightly denser output, common in short URLs and compact IDs. This tool encodes and decodes both, in several alphabet variants, in your browser.

The Alphabet Has to Match

An alphabet is the ordered list of characters a base uses. Different systems use the same 58 characters in different orders, and they are not interchangeable:

AlphabetUsed by
Base58 Bitcoin / IPFSBitcoin, most cryptocurrencies, IPFS CIDs
Base58 RippleThe XRP Ledger (reordered alphabet)
Base58 FlickrFlickr short URLs (lowercase before uppercase)
Base62 standard0–9, then A–Z, then a–z
Base62 inverted0–9, then a–z, then A–Z (POSIX-style)

Decode a Bitcoin address with the Ripple alphabet and you'll get nonsense, because the characters map to different numbers. Always pick the alphabet of the system you're working with.

Base58Check: Catching Typos

Bitcoin addresses and WIF keys use Base58Check, which this tool supports with the checksum option. It appends a 4-byte checksum — the first four bytes of a double SHA-256 of the payload — before encoding. On decode, the tool recomputes that checksum and rejects the input if it doesn't match, so a single mistyped character is caught instead of silently producing a different, valid-looking address.

Be clear on what this is: the checksum provides integrity (detecting accidental corruption), not security. It isn't a signature — anyone can recompute it over altered data — so it protects against typos and transmission errors, not against a deliberate forgery.

Encoding Is Not Encryption

As with any base encoding, this is a reversible representation, not protection. There's no key and no secrecy — anyone can decode the output. Base58Check adds error-detection on top, but still nothing hidden. Use encryption if data needs to stay private.

Frequently Asked Questions

Why does Base58 leave out some characters?
It omits 0, O, I and l because they're easily confused when read or copied by hand. Removing them makes addresses and keys more robust against transcription errors, which is why Bitcoin and IPFS use Base58 rather than a denser encoding.
What's the difference between the Bitcoin, Ripple and Flickr alphabets?
They use the same 58 characters but in different orders, so they produce different output for the same data and aren't interchangeable. Pick the one the system you're working with uses — Bitcoin/IPFS for most cases, Ripple for the XRP Ledger, Flickr for its short URLs.
What does Base58Check add?
A 4-byte checksum, computed as the first bytes of a double SHA-256 of the payload, appended before encoding. On decode it's verified, so a mistyped character is caught rather than producing a different valid-looking address. It detects errors; it isn't a signature and doesn't provide security.
Can I use this to secure data?
No. Base58 and Base62 are encodings — reversible and keyless — so anyone can decode the output. The checksum option adds error detection, not secrecy. If you need to protect data, encrypt it; encoding only changes how bytes are written.
Base58 or Base62 — which should I use?
Use Base58 (usually the Bitcoin alphabet) when the value may be read or typed by people, or to interoperate with crypto and IPFS. Use Base62 for compact machine-generated IDs and short URLs where the extra characters don't cause confusion. Match whatever your target system expects.
