What a Property List Is

A property list (plist) is Apple's format for storing structured data — app settings, preferences, Info.plist metadata, configuration profiles — across macOS and iOS. It holds the familiar building blocks: dictionaries, arrays, strings, numbers, booleans, dates and raw binary data. This tool parses a plist and shows it as readable JSON (and can convert it back to XML), computing a SHA-256 of the file, all in your browser.

Two Encodings: XML and Binary

EncodingLooks likeWhere it's used
XML plistText, <dict>/<key> tagsHand-edited files, source control, readable config
Binary plistStarts with bplist00, compact bytesWhat iOS and macOS actually store at runtime

Both describe the same data; the binary form just trades readability for size and speed. The tool detects which one you've given it — reading the bplist00 header for binary, or parsing the XML otherwise — so you don't have to specify. Parsing the binary form is the harder part, and many viewers can't do it; this one decodes the binary object table directly.

A Worked Example You Can Reproduce

A plist containing a name, a version number, a boolean, a float, an array and a nested dictionary converts to: 

{
  "Enabled": true,
  "Name": "BitDark",
  "Nested": { "x": 1, "y": 2 },
  "Ratio": 0.5,
  "Tags": ["a", "b", "c"],
  "Version": 3
}

The same data produces the identical JSON whether it came from an XML plist or its binary bplist00 equivalent — which is the point: the tool reads either encoding and gives you one consistent, readable result, with booleans, numbers, strings, arrays and nested dictionaries all mapped to their JSON counterparts.

A Note on Types JSON Doesn't Have

Plist has two types JSON lacks a native form for: <date> and <data> (raw binary, stored as Base64). When converting to JSON these are represented in a JSON-friendly form rather than a true date or byte type, so a JSON round trip won't always reproduce them exactly as the original plist encoded them. For dictionaries, arrays, strings, numbers and booleans the mapping is exact; just keep the date/data caveat in mind if a file relies on them.

Frequently Asked Questions

Can it read binary plists, or only XML?
Both. It detects the bplist00 header and decodes the binary object table directly, as well as parsing XML plists. That's useful because the binary form is what iOS and macOS store at runtime, and many online viewers can't read it.
Why convert a plist to JSON?
Plist's data model — dictionaries, arrays, strings, numbers and booleans — maps cleanly onto JSON, which is easier to read and to process with standard tools. It's a convenient, human-friendly view of the same structure, especially for a binary plist you couldn't otherwise read.
Will converting to JSON and back preserve everything?
For dictionaries, arrays, strings, numbers and booleans, yes. But plist dates and raw binary data don't have native JSON types, so they're shown in a JSON-friendly form and a round trip may not reproduce those exact types. Keep that in mind for files that use date or data values.
Do I need a Mac to use this?
No. It runs entirely in your browser on any platform, so you can inspect an Info.plist, preferences file or configuration profile from Windows or Linux without Apple's tools.
Is my plist uploaded anywhere?
No. Parsing and the SHA-256 hash run entirely in your browser, so nothing you load is sent to a server. That makes it safe to inspect preferences or configuration files that may contain sensitive settings.
