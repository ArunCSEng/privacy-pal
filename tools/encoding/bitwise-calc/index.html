What the Calculator Does

Why Word Size Changes the Answer

Bitwise operations happen inside a fixed number of bits, and the tool masks every result to the width you pick. The same operation gives different numbers at different widths:

Operation8-bit32-bit
NOT 5250 (0xFA)4294967290 (0xFFFFFFFA)
1 << 7128128

Choosing the width that matches your data — a uint8_t, a 32-bit register, a 64-bit field — is what makes the calculator model your actual code. A value that overflows out of an 8-bit word simply isn't there at 8 bits.

Signed vs Unsigned: the Same Bits, Two Numbers

A bit pattern has no inherent sign; how you read it is a choice. In 8 bits, 11111111 is 255 read as unsigned and −1 read as two's-complement signed. The tool shows both for every result, so you can see, for example, that an 8-bit NOT 5 is 250 unsigned and −6 signed — the same byte, two interpretations.

Arithmetic vs Logical Right Shift — the Common Trap

There are two right shifts, and they differ only on negative numbers:

  • >> (sign-propagating). Fills the vacated top bits with the sign bit, preserving sign — it's how you halve a signed number. In 8 bits, 254 >> 1 treats 254 as −2, giving −1 (0xFF, 255 unsigned).
  • >>> (zero-fill). Always fills with zeros, treating the value as unsigned. In 8 bits, 254 >>> 1 gives 127 (0x7F).

Same input, different results — 255 versus 127 — which is exactly the bug that appears when code uses the wrong shift on signed data. The calculator lets you see both so you can pick the right one.

A Worked Example You Can Reproduce

Set 8-bit width and try these; the results are exact:

NOT 5      → 250 unsigned / −6 signed
254 >> 1   → 255   (arithmetic)

At 64-bit width the results stay exact too: 0xFFFFFFFFFFFFFFFF AND 0xF0F0F0F0F0F0F0F0 gives 0xF0F0F0F0F0F0F0F0. That's because the tool computes with arbitrary-precision integers (BigInt), so 64-bit values don't lose precision the way ordinary floating-point numbers would above 253.

Frequently Asked Questions

Why does NOT give a different number at 8-bit and 32-bit?
Because NOT flips every bit within the chosen width. At 8 bits, NOT 5 flips 8 bits to give 250; at 32 bits it flips 32 bits to give 4294967290. The operation is the same — the word size determines how many bits are involved. Pick the width that matches your data.
What's the difference between >> and >>>?
>> is a sign-propagating (arithmetic) shift: it keeps the sign bit, so it halves signed numbers correctly. >>> is a zero-fill (logical) shift that treats the value as unsigned. They differ only for negative numbers — for example 8-bit 254 gives 255 with >> but 127 with >>>.
How can the same result be both 255 and −1?
A bit pattern carries no sign by itself. 8-bit 11111111 is 255 when read as unsigned and −1 when read as two's-complement signed. The tool shows both interpretations so you can see which one your code intends.
Are 64-bit calculations accurate?
Yes. The calculator uses arbitrary-precision integers (BigInt), so 64-bit operations are exact. Ordinary JavaScript numbers lose precision above 2^53, but that doesn't affect this tool because it doesn't use floating-point for the bit math.
Can I enter values in hex or binary?
Yes. Use the input-format pills to enter operands as hexadecimal (0x…) or binary (0b…) as well as decimal, and the result is shown in decimal, hex, octal and as a bit grid at the same time.
