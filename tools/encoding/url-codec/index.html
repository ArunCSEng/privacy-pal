Why URLs Need Encoding

A URL may contain only a limited set of characters, and some of them — : / ? # & = + — have structural meaning. Spaces, accents and most symbols aren't allowed at all. Percent-encoding (RFC 3986) replaces each disallowed byte with % followed by its two-digit hex value, so any text can travel safely inside a URL. This tool encodes and decodes that format and parses a full URL into its parts, entirely in your browser.

Component vs Full-URL Mode

The two modes matter because you encode a piece of a URL differently from a whole URL:

ModeWhat it encodesUse for
ComponentEverything except letters and digits, including : / ? #A single query value or path segment
Full URLOnly invalid characters (e.g. spaces); keeps : / ? # & = intactA complete URL you want to stay working

Using the wrong mode is the usual cause of a double-encoded or broken link: encode a whole URL in Component mode and its slashes and colons get escaped; encode a value in Full-URL mode and an embedded & or = leaks into the surrounding query.

A Worked Example You Can Reproduce

Encode https://ex.com/a b?x=1&y=a/b#top in each mode:

Component: https%3A%2F%2Fex.com%2Fa%20b%3Fx%3D1%26y%3Da%2Fb%23top
Full URL : https://ex.com/a%20b?x=1&y=a/b#top

Component mode escaped the separators; Full-URL mode left the structure and only fixed the space. These match the browser's own encodeURIComponent and encodeURI, and decoding either returns the original string exactly — encoding here is lossless and reversible.

Multi-Byte Characters

Non-ASCII characters are encoded as their UTF-8 bytes, each byte becoming one % pair. The character é is UTF-8 bytes C3 A9, so it encodes to %C3%A9; an emoji becomes four pairs. That's why a single accented letter can turn into several percent sequences — it's correct, not a bug.

Parsing a URL

The parser splits a URL into protocol, host, port, path, hash and a table of query parameters, with each value decoded as the server would read it. It's useful for inspecting a long or messy link, checking a redirect target, or reading exactly which parameters a page was called with.

Frequently Asked Questions

What's the difference between the two encoding modes?
Component mode encodes every character that isn't a letter or digit, including the structural ones like : / ? #, so it's safe for a single query value or path segment. Full-URL mode preserves those structural characters and only encodes what's invalid, such as spaces, so a complete URL keeps working.
Why did one character become several percent codes?
Non-ASCII characters are encoded as their UTF-8 bytes, and each byte is one percent pair. An accented letter like é is two bytes (%C3%A9) and an emoji is four, so a single character can expand into several sequences. That's correct UTF-8 percent-encoding.
Is percent-encoding reversible?
Yes. Decoding returns the exact original text, so encoding is lossless. Just be sure to decode with the matching expectation — a value encoded in Component mode decodes cleanly, while decoding a whole URL you can treat structural characters as intact.
Does encoding make a URL secure?
No. Percent-encoding is a transport format, not encryption — anyone can decode it. It ensures characters travel safely inside a URL and helps prevent values from breaking the URL's structure, but it doesn't hide or protect the data.
Is my input uploaded anywhere?
No. Encoding, decoding and parsing all run in your browser using its built-in URL functions, and nothing you paste is sent to a server. It's safe to work with URLs that contain tokens or other sensitive values.
