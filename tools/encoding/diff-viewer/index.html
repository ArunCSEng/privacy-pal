What the Diff Viewer Does

Paste two versions of text or code and this highlights what changed between them, line by line: additions, deletions and unchanged lines, with a count of each. You can view the result side by side (old on the left, new on the right) or as a unified diff with + and - markers, the format you see in patches and pull requests. Everything runs in your browser.

It Aligns Lines Properly, Not Just Row by Row

The quality of a diff is in how it handles an insertion. A naive comparison that lines up row 1 with row 1, row 2 with row 2, and so on, falls apart the moment a single line is added near the top — every line after it looks "changed." This tool instead uses the longest common subsequence (LCS) algorithm, the same approach behind git diff and standard diff libraries. It finds the longest run of lines the two versions share and aligns around it, so only the real changes are marked.

The difference is easy to see: insert one new line into the middle of a three-line file and this reports exactly one addition and zero deletions — not a cascade of false changes in the lines below.

Line-Level, Not Character-Level

One thing to know about the scope: comparison is done per line. If you change a single character in a line, that line shows as one deletion plus one addition — the whole old line removed and the whole new line added — rather than highlighting just the changed characters within it. That's ideal for code and configuration, where whole-line changes are the unit that matters; for prose where you want word-by-word highlighting, a character-level diff is a different tool.

Side-by-Side vs Unified

  • Side-by-side puts the two versions in parallel columns — best for reading context and seeing what replaced what.
  • Unified stacks the changes with +/- markers — the compact format used in patches, commits and code review.

How to Use the Tool

  1. Paste the original on the left and the modified version on the right.
  2. Choose a view — side-by-side or unified — and read the highlighted additions and deletions.
  3. Use Swap to reverse which side is "original," or Clear to start over.
  4. Check the counts for a quick summary of how much changed.

Where It's Useful

  • Code and config review — compare two revisions of a file or snippet before committing.
  • Spotting edits — see exactly what changed between two drafts, logs or API responses.
  • Exact-line comparison. Differences in whitespace or line endings count as changes, since the tool compares line content literally — useful when trailing spaces or tabs matter.
  • Runs locally. Both texts are compared in your browser — nothing is uploaded — so it's safe for private code or documents.

Frequently Asked Questions

Does it highlight the exact characters that changed in a line?
No — comparison is line by line. A changed line appears as the old line deleted and the new line added, not as an in-line character highlight. That suits code and configuration; for word-level highlighting within a line you'd want a character-level diff tool instead.
Why is this better than lining the files up row by row?
Because a single inserted or deleted line would throw off every line after it in a row-by-row comparison. The LCS algorithm finds the lines the two versions actually share and aligns around them, so only genuine changes are marked — the same method git and standard diff tools use.
What's the difference between the two views?
Side-by-side shows the old and new versions in parallel columns, which is easy to read for context. Unified stacks the changes with + and - markers in one column, the compact format used in patches and code review. They show the same diff, formatted differently.
Does whitespace count as a difference?
Yes. Lines are compared exactly, so a difference in trailing spaces, tabs or indentation shows up as a change. That's helpful when whitespace matters, but means reformatted-but-equivalent lines will appear as edits.
Is my text uploaded anywhere?
No. The comparison runs entirely in your browser, so nothing you paste is sent to a server. You can safely diff private source code, configuration or documents.
