What This Tool Does

Cron schedules recurring jobs on Unix-like systems, and its five-field syntax is compact but easy to get wrong. This tool lets you check an expression before you install it: type a cron line and it validates the fields, describes the schedule in plain English, and lists the next run times. It runs entirely in your browser — nothing you enter is sent anywhere — so it is a quick, private way to confirm that a schedule means what you think it does.

How to Use the Tool

  1. Enter an expression — type it into Cron Schedule Expression. Five space-separated fields in the order minute, hour, day-of-month, month, day-of-week, or a macro such as @daily. The field order is printed under the box if you lose track.
  2. Or use a preset — Every 15 Min, Nightly at 2 AM, Weekdays 9 AM and Quarterly load working expressions you can then edit, which is quicker than writing one from scratch.
  3. Click Validate Schedule — the expression is checked field by field and described in plain English.
  4. Read the run table — Next 10 Scheduled Execution Occurrences lists each upcoming run with its Local System Timestamp, its UTC Timestamp in ISO 8601, and the Relative Delay until it fires. Compare the two time columns if your server does not run in your local zone.
  5. Correct any errors — a failure names the offending field and why, so you can fix just that one.

The commonest errors are a value outside its field's range, a sixth field copied from a seconds-based scheduler, and a day-of-week where a day-of-month was meant.

The Five Fields

A standard cron expression has five fields, separated by spaces:

FieldRangeMeaning
Minute0–59Minute of the hour
Hour0–23Hour of the day (24-hour)
Day of month1–31Day of the month
Month1–12Month (names like JAN also accepted)
Day of week0–60 and 7 are both Sunday (names like MON accepted)

So 30 2 * * 1 is "02:30 every Monday", and */15 * * * * is "every 15 minutes".

Ranges, Lists and Steps

Each field can be more than a single value. A range uses a hyphen (1-5 in day-of-week is Monday to Friday); a list uses commas (1,15 in day-of-month is the 1st and 15th); and a step uses a slash (*/15 is every 15th value, and 0-30/10 gives 0, 10, 20, 30). The tool checks each field against its allowed range and reports a clear error — which field and why — if something is out of bounds or malformed.

The Day-of-Week Rule

One rule catches people out: when both the day-of-month and the day-of-week fields are restricted, cron combines them with OR, not AND. 0 0 1 * 1 runs on the 1st of the month and on every Monday — not only on a 1st that happens to be a Monday. If just one of the two is set (the other left as *), only that one applies. This tool follows the OR rule when it works out the run times, so its preview matches what a real daemon does.

Macros

Cron also accepts shorthand macros, which the tool expands to their five-field form: @hourly = 0 * * * *, @daily/@midnight = 0 0 * * *, @weekly = 0 0 * * 0, @monthly = 0 0 1 * *, and @yearly/@annually = 0 0 1 1 *. The one exception is @reboot, which runs at start-up and has no fixed clock time, so there is no next-run schedule to show for it.

A Worked Example You Can Reproduce

Enter 0 9 * * 1-5. The tool reads it as "09:00, Monday through Friday" and lists the next ten run times — the coming weekdays at 09:00, skipping Saturday and Sunday. Change it to */30 9-17 * * 1-5 and the description becomes "every 30 minutes, between 09:00 and 17:00, Monday through Friday", with run times half-hourly across the working day. Because the next-run times are in your local time zone, they line up with a server only if the server uses the same zone.

Frequently Asked Questions

What do the five fields in a cron expression mean?
In order they are minute (0-59), hour (0-23), day of month (1-31), month (1-12), and day of week (0-6, where 0 and 7 are both Sunday). So 30 2 * * 1 means 02:30 every Monday. Each field can be a single value, a list, a range, or a step, or * for every value.
How do ranges, lists and step values work?
A range is written with a hyphen (1-5 = Monday to Friday), a list with commas (1,15 = the 1st and 15th), and a step with a slash (*/15 in the minute field = every 15 minutes, or 0-30/10 = 0, 10, 20, 30). You can combine them, and this tool validates each field against its allowed range.
If I set both day-of-month and day-of-week, how are they combined?
With OR, not AND. When both the day-of-month and day-of-week fields are restricted (neither is *), cron runs on a day that matches either one. So 0 0 1 * 1 runs on the 1st of the month and on every Monday, not only on a 1st that falls on a Monday. This tool follows that rule when computing run times.
What do @daily and the other macros mean?
They are shorthands: @hourly is 0 * * * *, @daily (or @midnight) is 0 0 * * *, @weekly is 0 0 * * 0, @monthly is 0 0 1 * *, and @yearly (or @annually) is 0 0 1 1 *. This tool expands them and treats them as the equivalent five-field expression. @reboot has no fixed time, so it has no next-run schedule to show.
Which time zone are the next run times in?
This tool computes the next run times in your browser's local time zone. A real cron daemon uses the server's time zone (and may be affected by daylight-saving changes), so if your server runs in a different zone, adjust accordingly. The schedule itself is the same; only the displayed clock times shift.
