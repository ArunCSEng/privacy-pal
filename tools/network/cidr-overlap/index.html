What This Tool Does

When you plan addressing across several networks — subnets in a routing table, VPCs you want to peer, ranges handed to different teams — two blocks must not cover the same addresses unless you mean them to. An accidental overlap makes routing ambiguous and blocks cloud peering. This tool takes a list of CIDR blocks, compares every pair, and reports the ones that overlap, so you can catch a conflict before it reaches production. Paste the list, and it checks them in your browser; nothing you enter is sent anywhere.

How Overlap Is Decided

Every CIDR block covers a contiguous range of addresses, from its network address to its last address. The tool converts each block you enter into that numeric range — a first and a last value — and then two blocks overlap exactly when each one's first address is less than or equal to the other's last. This interval test is precise and works the same for IPv4 and IPv6, with IPv6 handled as 128-bit big integers. It is the same reasoning a router or an IPAM system uses, reduced to its essence.

Kinds of Overlap It Reports

TypeMeaning
IdenticalTwo entries cover exactly the same range — usually a duplicate.
ContainmentOne block fully contains the other, like 10.0.0.0/16 around 10.0.5.0/24.
PartialThe ranges intersect without one containing the other.

Each conflicting pair is listed with the type, so you can see not just that there is a clash but what kind it is.

A Worked Example You Can Reproduce

Paste this list and run the check: 

10.0.0.0/16
10.0.5.0/24
10.1.0.0/16
192.168.0.0/24
192.168.0.0/24

The tool reports two conflicts. 10.0.0.0/16 and 10.0.5.0/24 are a containment overlap — the /24 sits inside the /16. The two 192.168.0.0/24 lines are an identical overlap (a duplicate). The 10.1.0.0/16 block does not conflict with anything: it is adjacent to 10.0.0.0/16 but shares no address. You can confirm the containment with Python: ipaddress.ip_network('10.0.5.0/24').subnet_of(ipaddress.ip_network('10.0.0.0/16')) returns True.

Frequently Asked Questions

What counts as an overlap between two CIDR blocks?
Two blocks overlap when they share at least one address. That happens when one block contains the other (for example 10.0.0.0/16 contains 10.0.5.0/24), when they are identical, or when their ranges partially intersect. The tool reports all three; blocks that sit next to each other without sharing an address, like 10.0.0.0/24 and 10.0.1.0/24, do not overlap.
Why do overlapping subnets cause problems?
Overlapping ranges make routing ambiguous: a destination address can match more than one entry, and the result depends on longest-prefix match and local policy rather than your intent. In cloud networking, two VPCs or VNets with overlapping CIDRs usually cannot be peered, and VPN or transit setups fail or route unpredictably. Finding overlaps before provisioning avoids these conflicts.
How does the tool decide whether two blocks overlap?
It converts each CIDR to the numeric range of addresses it covers — a first and last value — and two blocks overlap when the first of each is less than or equal to the last of the other. Using numeric ranges makes the check exact for both IPv4 and IPv6, with IPv6 handled as 128-bit big integers.
Can it check IPv4 and IPv6 together?
It parses both, but an IPv4 block and an IPv6 block never overlap — they are separate address spaces. Overlaps are only reported within the same family, so you can paste a mixed list and the tool compares IPv4 against IPv4 and IPv6 against IPv6.
Is my list uploaded anywhere?
No. The CIDR blocks you paste are parsed and compared in your browser, and nothing is sent to a server. The page makes no network request for your input, so you can check internal addressing plans without exposing them.
