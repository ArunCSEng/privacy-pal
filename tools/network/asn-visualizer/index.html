What This Tool Does

The internet is a mesh of Autonomous Systems (AS) — large networks, each with an AS number — and BGP is the protocol that stitches them together. As a route is advertised from network to network, BGP records the AS-path: the list of ASes it crossed. This tool takes AS-paths you paste and draws them as a diagram, counting prepends and flagging loops, so you can see the shape of a path at a glance. It is a visualiser for paths you already have — from a looking glass, a route collector, a lab or your own notes — and it runs entirely in your browser with no lookups, so nothing you type leaves your machine.

How to Use the Tool

  1. Enter your paths — type or paste into AS-Path Entries, one path per line. Separators are flexible: 64512 3356 15169, 64512, 3356, 15169 and 64512 -> 3356 -> 15169 all parse, and the AS prefix is optional. Put each path you want to compare on its own line.
  2. Or start from the sample — Load Sample Paths fills the box with a set that includes a clean path, a prepended one and a loop, which is the fastest way to see what each result looks like.
  3. Click Visualize Paths — the canvas draws each path as a row of AS hops with the origin marked, and the table below fills in.
  4. Read the table columns — Terminal / Peer AS (Left) is the AS nearest you, Origin AS (Right) is the AS that announced the prefix, and Hop Count, Prepends and Loop Status give you the analysis per path.
  5. Iterate — edit a line and visualize again to compare; Clear Workspace empties both the input and the canvas.

If a path does not appear, check that every entry is a number in the valid AS range — stray text or an empty line is skipped rather than drawn.

Reading an AS-Path

An AS-path is usually written left to right in the order BGP stores it, with the AS nearest you first and the origin AS — the one that announced the prefix — last. Routers prefer shorter paths, all else being equal, and they use the path to avoid loops: if a router sees its own AS already in the path, it rejects the route. The tool reports each path's origin, its first (terminal) AS, and the hop count, and lays the hops out so you can compare one path against another.

Prepending and Loops

Two patterns are worth calling out, and the tool detects both:

  • AS-path prepending — a network repeats its own AS number several times in a row to make a path look longer, nudging BGP's shortest-path preference toward a different route. It is a normal traffic-engineering technique. The tool counts consecutive repeated AS numbers as prepends.
  • Loops — a valid path should not revisit an AS in a non-adjacent position. When an AS number reappears after a different one, the tool flags the path as a loop (distinguishing that from a simple run of repeats, which is prepending).

Frequently Asked Questions

What is a BGP AS-path?
As a route travels across the internet between Autonomous Systems (networks, each with an AS number), BGP records the list of ASes it passed through — the AS-path. Read right to left it runs from the origin AS that announced the prefix to the AS nearest you, and routers use its length and contents to choose between routes and to prevent loops.
Does this tool look up live routes or AS names?
No. It draws the AS-paths you paste in; it does not query BGP, a looking glass or a WHOIS database, and it does not map AS numbers to organisation names. It works entirely offline on your input, which is why nothing you type is sent anywhere. To get a real path or an AS owner, use a looking glass or an RIR WHOIS service.
What is AS-path prepending, and how does the tool show it?
Prepending is when a network lists its own AS number several times in a row to make a path look longer, so BGP's shortest-path preference steers traffic to a different route — a common traffic-engineering trick. The tool counts consecutive repeated AS numbers in each path and reports them as prepends.
How does it detect a loop?
A valid AS-path should never pass through the same AS twice in non-adjacent positions; if it does, the route loops, which BGP normally rejects. The tool flags a path as a loop when an AS number reappears after a different one (as opposed to a run of repeats, which it reads as prepending).
What input format does it accept?
One path per line, as AS numbers separated by spaces, commas or arrows — for example 64512 -> 3356 -> 174 -> 15169 or AS64512 AS3356 AS15169. The AS prefix is optional, and 32-bit AS numbers are accepted. Enter several lines to compare paths side by side.
