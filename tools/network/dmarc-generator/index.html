DMARC Deployment Phasing & Policy Alignment

DMARC (Domain-based Message Authentication, Reporting, and Conformance) prevents email spoofing by verifying that the author's visible From: domain aligns with underlying SPF and DKIM authentication domains:

  • Phase 1: Monitoring (p=none): No incoming mail is blocked or quarantined. Mailbox providers (such as Gmail, Microsoft 365, and Yahoo) send XML aggregate performance telemetry reports to your rua inbox detailing all sending IP addresses using your domain.
  • Phase 2: Soft Enforcement (p=quarantine): Messages failing authentication alignment are redirected into the recipient's spam, junk, or quarantine folder. You can enforce this on a subset using pct=25 or pct=50 to mitigate delivery risks.
  • Phase 3: Full Enforcement (p=reject): Mail receivers reject and drop non-compliant messages outright at the SMTP boundary transfer phase, neutralizing direct domain impersonation attacks.

Strict vs. Relaxed Identifier Alignment

By default, relaxed alignment (adkim=r, aspf=r) allows subdomains (e.g., marketing.example.com) to pass alignment against an organizational root domain (example.com). In strict alignment (adkim=s, aspf=s), the exact domain in the visible From header must match the DKIM signing domain (d=) and the SPF Return-Path envelope domain.
