What This Tool Does

Every byte of header is a byte of payload you do not get. Start at a 1500-byte Ethernet MTU, add a VLAN tag, wrap it in a VPN, and the space left for actual TCP data shrinks each time — which is why tunnelled links so often misbehave in ways that look mysterious. This calculator makes the arithmetic explicit: pick your base MTU and the encapsulation layers in play, and it shows what each one costs and what MSS is left at the end.

How to Use the Tool

  1. Start from a preset — Standard Ethernet, WireGuard / IPv4, PPPoE Fiber and Cloud VPC / VXLAN each load a realistic combination of settings. Picking the closest one and adjusting is faster than building a scenario from scratch, and Reset Defaults returns to plain Ethernet.
  2. Set the base MTU — Base Physical MTU defaults to 1500 for standard Ethernet. Use 9000 if you are on jumbo frames, or whatever your provider specifies.
  3. Choose the IP versions — Outer IP Version is the header on the wire, costing 20 bytes for IPv4 or 40 for IPv6. Inner Tunnel IP Version only applies when you are encapsulating; leave it matched to the outer layer if you are not.
  4. Tick the encapsulation in play — PPPoE (8 bytes), an 802.1Q VLAN tag (4), QinQ (8), WireGuard, VXLAN and so on. Add every layer the traffic actually traverses, since they stack.
  5. Set TCP options — a bare TCP header is 20 bytes, but with timestamps and SACK it is typically 32, and 40 is the maximum. Most modern stacks negotiate timestamps, so 32 is often the realistic figure rather than 20.
  6. Read the breakdown table — each row names a Protocol Layer / Header Component, its Overhead Size, and the Running Remaining Payload after it, so you can see exactly where the budget goes rather than just the final number.

If the resulting MSS is lower than you expected, work up the table to find the layer that cost the most — it is usually an encapsulation you forgot was in the path.

MTU and MSS Are Not the Same Number

MTU is the largest frame a link will carry, headers included. MSS is the TCP payload that fits inside it once the IP and TCP headers are gone. On ordinary IPv4 Ethernet: 1500 − 20 (IP) − 20 (TCP) = 1460, the number you see constantly in packet captures. Switch the outer layer to IPv6 and the IP header doubles to 40 bytes, so the same link gives 1440. Nothing has gone wrong; the headers simply got bigger.

Why Tunnels Break Large Transfers

The symptom is distinctive: ping works, SSH connects, a web page starts loading and then hangs. That is an MTU black hole. Small packets fit inside the reduced tunnel MTU, so anything interactive succeeds. A full-size packet does not, and the router that cannot forward it is supposed to return an ICMP fragmentation needed message so the sender backs off — this is path MTU discovery. Plenty of networks filter that ICMP type as a blanket security measure, so the message never arrives. The sender assumes the packet was lost, retransmits the same oversized packet, and the transfer stalls indefinitely.

The reliable fix is not to rely on discovery at all. MSS clamping at the tunnel edge rewrites the MSS value during the TCP handshake, so both ends agree on a segment size that fits before any data flows. That is what the number this calculator gives you is for.

A Worked Example You Can Reproduce

Take a WireGuard tunnel over IPv4 Ethernet. Start at 1500. The outer IPv4 header takes 20, leaving 1480. UDP takes 8, leaving 1472. The WireGuard header takes 32, leaving 1440 — that is the tunnel's MTU. Inside it, the inner IPv4 header takes another 20 and the TCP header 20 more, so the MSS is 1400. Set TCP options to 32 bytes instead of 20 and it drops to 1388.

Now add a VLAN tag to the underlay: 4 bytes come off the top and every figure moves down by four, giving an MSS of 1396. Each number is reachable by subtraction, so you can check the tool against a sheet of paper — which is worth doing once, because it makes the running total column much easier to read afterwards.

Frequently Asked Questions

What is the difference between MTU and MSS?
MTU is the largest frame a link will carry, headers included — 1500 bytes on standard Ethernet. MSS is how much TCP payload fits inside that once the IP and TCP headers are subtracted. On plain IPv4 Ethernet that is 1500 minus 20 for IP and 20 for TCP, giving the familiar 1460.
Why does my VPN break large transfers but ping fine?
Small packets fit; large ones do not. A tunnel adds its own headers, so a full-size packet that was fine on the local link becomes too big once encapsulated. If the ICMP messages that would report this are filtered, the sender never learns and simply retransmits forever — the classic MTU black hole, where handshakes succeed and bulk transfers stall.
What is path MTU discovery, and why does it fail?
A sender marks packets as Do Not Fragment and relies on routers returning an ICMP fragmentation-needed message to learn the smallest MTU on the path. Many networks block that ICMP type, so the message never arrives and the sender keeps sending oversized packets. Clamping MSS at the tunnel edge avoids depending on it.
Why is PPPoE 8 bytes?
PPPoE adds a 6-byte session header plus a 2-byte PPP protocol field, so 8 bytes in total, which is why many DSL and fibre links run at 1492 rather than 1500. The calculator includes it as a toggle because it is the single most common reason a connection is not a round 1500.
Does this tool measure my actual path MTU?
No. It is a calculator: it works out what the MSS should be for the headers you select. Measuring a real path means sending probes, for example ping with the don't-fragment flag at decreasing sizes. Use the calculated figure as the expected answer, then confirm it against the live path.
