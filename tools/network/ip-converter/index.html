What This Tool Does

An IP address is a number, and a number can be written many ways. This tool takes an IPv4 or IPv6 address — in any of the common notations — and shows you every other form at once: dotted-decimal, a single integer, hexadecimal, octal, binary, the fully expanded and RFC 5952-compressed IPv6 forms, and the reverse-DNS PTR name. It is useful when a log, a config file or an API hands you an address in a shape you did not expect. It runs entirely in your browser and makes no network requests.

IPv4: One Address, Several Forms

An IPv4 address is 32 bits. The familiar dotted-decimal form just splits those bits into four 8-bit octets for readability — the underlying value is a single number. Take 192.168.1.1:

NotationValue
Dotted decimal192.168.1.1
Integer (dword)3232235777
Hexadecimal0xc0a80101
Binary11000000.10101000.00000001.00000001
Reverse DNS (PTR)1.1.168.192.in-addr.arpa

The integer comes straight from the bits: (192 × 224) + (168 × 216) + (1 × 28) + 1 = 3232235777. You can confirm any of these with Python: int(ipaddress.IPv4Address('192.168.1.1')).

IPv6: Expanding and Compressing

IPv6 addresses are 128 bits written as eight 16-bit groups, and they are almost always shortened. RFC 5952 defines exactly how, so that one address has one canonical text form:

  • Suppress leading zeros in each group — 0db8 becomes db8.
  • Replace the longest run of two or more all-zero groups with ::, which may appear only once.
  • If two runs are equally long, compress the first one.
  • Write hex digits in lowercase.

So 2001:0db8:0000:0000:0000:ff00:0042:8329 compresses to 2001:db8::ff00:42:8329, and the tool will expand it back again. A single zero group is left alone rather than compressed, which is the rule people most often get wrong.

Why Parsers Disagree

The conversions above are pure arithmetic, but how a given system reads an unusual notation is not standardised. Libraries that follow the historical inet_aton() behaviour accept hex and octal parts, so 0177.0.0.1 may be read as 127.0.0.1; stricter modern parsers reject the same string. This is the practical reason to normalise before you compare: a security check that matches address strings can be slipped past by an equivalent address written differently, whereas one that parses the input to a canonical form first cannot. Seeing all the notations side by side makes that failure mode easy to understand.

Frequently Asked Questions

How does an IPv4 address become a single integer?
An IPv4 address is just 32 bits, written as four 8-bit octets for readability. Treating those 32 bits as one number gives the integer (or dword) form: 192.168.1.1 is (192 x 16777216) + (168 x 65536) + (1 x 256) + 1 = 3232235777. The same bits in base 16 are 0xc0a80101.
What are the RFC 5952 rules for compressing IPv6?
Drop the leading zeros in each 16-bit group; replace the longest run of two or more all-zero groups with ::; if two runs are the same length, compress the first one; and write hex digits in lowercase. A single zero group is not compressed, and :: may appear only once. This tool follows all of these.
What is the reverse-DNS PTR name for?
Reverse DNS maps an address back to a hostname, and it is queried under a special name built from the address backwards: 192.168.1.1 becomes 1.1.168.192.in-addr.arpa, while IPv6 uses each nibble in reverse under ip6.arpa. The tool builds that name for you, which is what you would look up to find a PTR record.
Why do different systems disagree about odd IP formats?
The arithmetic is unambiguous, but parsers are not. Older libraries following inet_aton accept octal and hexadecimal parts, so a leading zero can change the meaning, while stricter modern parsers in Go or Python reject those forms outright. That is why a filter that compares address strings can be fooled: normalise an address to one canonical form before validating it, rather than matching text.
Is my input uploaded anywhere?
No. The conversion is arithmetic done in your browser, and nothing you type is sent to a server. The page makes no network request for your input and performs no DNS lookup — it only builds the PTR name, it does not query it.
