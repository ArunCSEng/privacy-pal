What This Tool Does

A MAC address is the 48-bit identifier burned into (or assigned to) a network interface. Paste one in and this tool breaks it down: which bytes are the manufacturer prefix, what the flag bits in the first octet say, whether it looks like a randomized privacy address, how it is written in other notations, and what IPv6 link-local address it would derive. It runs entirely in your browser with no lookups, so nothing you enter is sent anywhere.

How to Use the Tool

  1. Enter a MAC address — any common notation works: 00:1A:2B:3C:4D:5E, 00-1A-2B-3C-4D-5E, Cisco-style 001a.2b3c.4d5e, or bare hex. A three-byte OUI prefix on its own is also accepted.
  2. Or try a sample — the four preset buttons are chosen to show different outcomes: VMware Sample matches a known vendor, Raspberry Pi is another real assignment, Randomized / U/L demonstrates a locally administered privacy address, and Multicast Sample shows a non-unicast address.
  3. Click Lookup MAC — the table fills with each Representation / Property and its Value.
  4. Check the flag bits first — before reading any vendor name, look at the U/L bit. If it reports a locally administered address, the bytes were generated by software and no vendor interpretation applies.
  5. Use the derived values — the alternate formats, the modified EUI-64 and the IPv6 link-local address are all listed, and the Action column copies any single row.

A vendor shown as unknown simply means the prefix is not in the built-in list, which covers common equipment rather than the whole IEEE registry.

OUI and Device Identifier

The six bytes split in half. The first three are the OUI (Organizationally Unique Identifier), which the IEEE assigns to a manufacturer — 00:50:56 belongs to VMware, for instance. The last three are chosen by that manufacturer to identify the individual interface. That is why a MAC can hint at what a device is.

One honest caveat about this tool: so that it needs no network, it carries a small built-in list of frequently seen prefixes rather than the full IEEE registry, which runs to tens of thousands of entries. If your address is not in that list, the tool says so — that means "not in my data", not "unregistered". For a definitive answer, search the IEEE registry.

The Two Bits That Matter

The low two bits of the first octet carry meaning, and the tool decodes both:

BitValueMeaning
I/G (bit 0)0Unicast — a single interface.
I/G (bit 0)1Multicast or broadcast (ff:ff:ff:ff:ff:ff).
U/L (bit 1)0Universally administered — a genuine IEEE-assigned OUI.
U/L (bit 1)1Locally administered — set by software, not the manufacturer.

Spotting a Randomized MAC

The U/L bit is how you recognise a privacy address. iOS, Android, Windows and macOS all rotate randomized Wi-Fi MAC addresses by default, and those are locally administered — so the U/L bit is set, and the first octet typically ends in 2, 6, A or E. When the tool reports a locally administered address, treat any vendor interpretation as meaningless: those bytes came from the operating system's random generator, not from an IEEE assignment. This is working as intended, and it is why MAC-based device tracking has largely stopped working.

EUI-64 and IPv6 Link-Local

IPv6 can build an interface identifier from a MAC address using modified EUI-64: insert FF:FE into the middle of the six bytes to make eight, then flip the U/L bit of the first byte. Prefix that with fe80:: and you have the link-local address the interface would use. The tool performs both steps, so you can see exactly where an fe80:: address came from — and why it embeds the hardware address, which is precisely the privacy concern that led to randomized and temporary IPv6 addresses.

A Worked Example You Can Reproduce

Enter 00:50:56:C0:00:08. The first octet 00 is binary 00000000, so I/G = 0 (unicast) and U/L = 0 (universally administered) — a real assigned address. The OUI 00:50:56 matches VMware in the built-in list, which is what you would expect from a virtual machine. The modified EUI-64 inserts FF:FE and flips the U/L bit, turning the leading 00 into 02, and the derived link-local address begins fe80::250:56ff:fec0:8. Now try A2:3B:4C:5D:6E:7F: the first octet A2 has the U/L bit set, so the tool reports a locally administered address — the signature of a randomized or manually assigned MAC, where no vendor lookup applies.

Frequently Asked Questions

What is an OUI?
The first three bytes of a MAC address are the Organizationally Unique Identifier, assigned by the IEEE to a manufacturer; the remaining three are chosen by that manufacturer for the individual device. So 00:50:56 identifies VMware. The IEEE registry holds tens of thousands of these assignments.
Why does my MAC show as an unknown organisation?
This tool ships with a small built-in list of common vendor prefixes — network equipment, virtualisation platforms and cloud hypervisors — rather than the full IEEE registry, because it works entirely offline with no lookups. An address outside that list is simply not in the bundled data; it does not mean the prefix is unregistered. Check the IEEE registry directly for a definitive answer.
What do the first octet's two low bits mean?
The lowest bit is I/G: 0 for a normal unicast address, 1 for multicast or broadcast. The next bit is U/L: 0 means the address is universally administered (a real IEEE-assigned OUI) and 1 means it is locally administered — set by software rather than the manufacturer. The tool shows both bits and what they imply.
How can I tell a randomized privacy MAC?
Look at the U/L bit. Phones and laptops rotate randomized Wi-Fi MACs that are locally administered, so that bit is set and the first octet usually ends in 2, 6, A or E. When the tool reports a locally administered address, any vendor guess is meaningless — the bytes were generated by the operating system, not assigned to hardware.
Is a MAC address a reliable identity?
No. A MAC address is software-settable: it can be changed with a single command, so it should never be the only thing authenticating a device. MAC filtering and MAC Authentication Bypass are easily defeated. Use 802.1X with certificates (EAP-TLS) or similar for real network access control.
