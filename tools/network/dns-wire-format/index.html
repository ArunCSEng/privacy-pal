What This Tool Does

A DNS query or response travels as a compact block of bytes — the wire format defined in RFC 1035. This tool works with that format in both directions. Give it a domain name and a record type and it builds the query packet those bytes would be, down to the transaction ID and the recursion-desired flag. Give it a packet you captured as hex — in Wireshark, say — and it decodes it: the 12-byte header and its flags, the question and answer sections, the label and compression-pointer encoding used for names, and each resource record. Either way the work happens in your browser: it performs no DNS lookup and transmits nothing, so it never sends the query it builds.

Building a query and then deconstructing its own output is a good way to learn the format: you see the same bytes from both sides.

The 12-Byte Header

Every DNS message starts with a fixed 12-byte header: a 16-bit transaction ID, a 16-bit flags field, and four 16-bit counts — questions, answers, authority records and additional records. The flags field is itself packed with smaller fields, and the tool breaks them out: QR (0 for a query, 1 for a response), the 4-bit opcode, the AA (authoritative), TC (truncated), RD (recursion desired) and RA (recursion available) bits, and the 4-bit RCODE result code.

Names: Labels and Compression Pointers

Names are not stored with dots. Each label is preceded by a length byte and the name ends with a zero byte, so example.com is 07 65 78 61 6d 70 6c 65 03 63 6f 6d 00 — a 7-byte label, a 3-byte label, then the terminator. To save space when the same name appears more than once, DNS uses a compression pointer: a byte whose top two bits are 11 (0xC0) signals a pointer, and the remaining 14 bits give an offset earlier in the packet to continue from. The tool follows these pointers, so a record that stores only c0 0c still shows its full name.

Building a Query

A question is only four things on the wire: the encoded name, a 16-bit type, a 16-bit class, and a header in front of them. The builder exposes exactly those. The record type list shows each option with its numeric code — A is 1, AAAA is 28, MX is 15, TXT is 16 — which is the number that actually goes into the packet. The transaction ID is the 16-bit value a resolver uses to match a reply to its question; it is arbitrary, and in real resolvers it is randomised to make off-path spoofing harder. The recursion desired flag is a single bit in the flags field: set it and the flags word reads 0x0100, clear it and you get 0x0000, which is the difference between asking a resolver to do the work and querying a server iteratively.

Because the builder writes the same bytes a real client would, you can construct a query and immediately deconstruct its own output to see every field you just set, which is the quickest way to learn where each one lives.

Frequently Asked Questions

What is the DNS wire format, and what can this tool do with it?
It is the binary layout (RFC 1035) a DNS query or response takes on the network: a 12-byte header, then the question section, then answer, authority and additional records. This tool works both ways — it builds a query packet from a domain name and record type, and it decodes a packet you paste as hex, for example one captured in Wireshark.
What is in the 12-byte header?
A 16-bit transaction ID, a 16-bit flags field, and four 16-bit counts: questions, answers, authority records and additional records. The flags pack several fields — QR (query or response), opcode, the AA/TC/RD/RA bits, and the 4-bit RCODE — which the tool breaks out individually.
How are domain names encoded?
A name is a series of labels, each preceded by a length byte, ending with a zero byte — so example.com is 07 'example' 03 'com' 00. There are no dots on the wire; the length bytes separate the labels. The tool reads these length-prefixed labels and reassembles the name with dots.
What is a compression pointer?
To avoid repeating a name, DNS lets a name end in a pointer to an earlier offset in the packet. A byte whose top two bits are 11 (0xC0) marks a pointer; the low 14 bits are the offset to jump to. The tool recognises these pointers and follows them, which is why an answer can show a full name even though the bytes only contain c0 0c.
Is my packet uploaded anywhere?
No. Everything you enter is handled in your browser and nothing is sent to a server. The tool performs no DNS lookup, and the query it builds is only ever displayed as bytes — it is never transmitted, so captured traffic and the names you query stay on your machine.
