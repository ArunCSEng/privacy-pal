Common Nginx Configuration Pitfalls & Vulnerabilities

Nginx configurations often contain subtle syntax and architecture pitfalls that pass casual reviews while opening critical security flaws or breaking routing rules:

  • Insecure Alias Traversal: Declaring location /files { alias /var/data/; } without a trailing slash on the location path permits path traversal attacks (e.g. /files../secret resolves to /var/secret).
  • Proxy_Pass Trailing Slash Stripping: Adding or omitting a trailing slash on proxy_pass fundamentally alters URI rewriting behavior. For instance, location /api/ { proxy_pass http://backend/; } strips /api/ from the forwarded request, whereas omitting the trailing slash forwards the full original request path.
  • Missing Semicolons & Unbalanced Braces: Nginx treats every block as a nested directive scope. A single omitted semicolon merges consecutive directives, causing parsing crashes during service reloads.
  • Information Disclosure: Omitting server_tokens off; exposes specific Nginx version headers to remote clients, aiding reconnaissance during automated vulnerability scans.
