UUID Structural Anatomy & Specifications

A Universally Unique Identifier (UUID) is a 128-bit identifier defined by RFC 4122 and RFC 9562, represented in canonical form as five hexadecimal groups separated by hyphens (8-4-4-4-12):

$$\text{urn:uuid:xxxxxxxx-xxxx-Mxxx-Nxxx-xxxxxxxxxxxx}$$

  • Version ($M$): The high 4 bits of the seventh byte define the UUID version (e.g., 1, 4, or 7).
  • Variant ($N$): The high 1 to 3 bits of the ninth byte define layout and multiplexing semantics. Standard RFC 4122/9562 variants require bits 10xx (hex 8, 9, a, or b).

Evaluating UUID Implementations

  • UUIDv4 (Random): 122 bits of cryptographically secure random entropy. The collision probability of two independently generated UUIDv4 tokens is negligibly small ($1$ in $2^{122}$).
  • UUIDv7 (Unix Epoch Time-Sorted): Combines a 48-bit millisecond Unix timestamp with 74 bits of entropy, optimizing performance for B-Tree database indexes while preventing fragmentation.
  • UUIDv1 (Timestamp & Node): 60-bit 100-nanosecond intervals since Oct 15, 1582, concatenated with clock sequence and a simulated 48-bit random Node MAC address to safeguard client hardware privacy.

Zero Network Egress Security Guarantee

Generating identification keys on public cloud endpoints risks server logging and exposure to middleboxes. BitDark produces all identifiers directly inside volatile memory. Zero entropy buffers or generated tokens are sent across the wire.
