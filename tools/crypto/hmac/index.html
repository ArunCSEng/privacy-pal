How HMAC Authentication Operates

A Hash-based Message Authentication Code (HMAC, defined in RFC 2104 and FIPS 198) uses a symmetric secret key in combination with an iterative cryptographic hash function. HMAC prevents length extension attacks that affect naive hash constructions like $\text{hash}(key \parallel message)$:

  • Inner Hash Pass: The secret key is XORed with an inner pad ($ipad$, byte 0x36 repeated), followed by the message.
  • Outer Hash Pass: The secret key is XORed with an outer pad ($opad$, byte 0x5C repeated), followed by the digest of the inner hash pass:

$$\text{HMAC}(K, m) = H\bigl((K \oplus opad) \parallel H((K \oplus ipad) \parallel m)\bigr)$$

Key Selection and Security Considerations

The security of an HMAC implementation depends heavily on the strength of the underlying hash function and the randomness of the secret key:

  • Key Length: Keys should have at least the same bit-length as the output size of the chosen hash function (e.g., 256 bits for SHA-256). Keys shorter than this standard lower the effective security threshold.
  • Algorithm Choice: HMAC-SHA-256 and HMAC-SHA-512 are universally recommended for modern applications, API signature verification (such as AWS Signature V4 and Webhooks), and JSON Web Signatures (HS256).
