What HMAC Is

HMAC is a keyed hash. Feed it a message and a secret key and it produces a short tag that proves two things to anyone who also holds the key: the message wasn't altered, and it came from someone who knows the key. A plain hash like SHA-256 proves only that data wasn't changed — anyone can recompute it. HMAC adds the key, so an attacker who tampers with the message can't produce a matching tag. This tool computes and verifies HMAC with the browser's Web Crypto API.

What HMAC Is Not

  • Not encryption. HMAC doesn't hide the message; it authenticates it. The message travels in the clear alongside its tag.
  • Not a digital signature. HMAC is symmetric — both sides share the same secret. Anyone who can verify a tag can also create one, so it proves authenticity between parties that trust each other, not to the public.

That's exactly what's needed for webhook and API request signing (Stripe and GitHub sign payloads this way), for JWTs using HS256, and for protecting cookies or tokens from tampering.

Change a single character of the key or message and the whole tag changes unpredictably — that's the property that makes tampering detectable.

Choosing the Algorithm and Key

Use HMAC-SHA-256 unless you have a reason not to; SHA-384 and SHA-512 are fine for longer tags. A note on HMAC-SHA-1: although SHA-1 is broken for general collision resistance, HMAC-SHA-1 is not broken, because HMAC doesn't rely on that property — it remains secure and is still widely deployed. Even so, prefer SHA-256 for new systems.

The key matters more than the algorithm choice. HMAC's security rests on the key being secret and having enough entropy, so use a long random key — ideally at least as many bytes as the hash output (32 bytes for SHA-256) — not a short word. The key-encoding selector (text, hex or Base64) only tells the tool how to interpret the key you paste; it doesn't change the security.

Verifying a Tag — and Doing It Safely in Code

To verify, paste the expected tag into the comparison field; the tool recomputes the HMAC and reports whether they match. One important point for real code: when your server compares an incoming HMAC against the expected one, use a constant-time comparison (crypto.timingSafeEqual in Node, hmac.compare_digest in Python). A naive == can leak, through tiny timing differences, how much of the tag an attacker has guessed. This browser tool compares locally for convenience; the constant-time rule is about your production verifier.

How to Use the Tool

  1. Pick the hash algorithm (SHA-256 is the default choice).
  2. Enter the secret key and set its encoding (text, hex or Base64) to match how the key is stored.
  3. Enter the message to compute the HMAC tag in hex and Base64.
  4. Verify by pasting an expected tag; the tool reports a match or mismatch.

Scope and Limits

  • A learning, testing and interop tool. Useful for checking that two systems compute the same tag, or understanding a signing scheme — not for managing production secrets.
  • Not key management. The key is visible on screen; real systems keep signing keys in a secrets manager and rotate them.
  • Authenticity, not confidentiality. If you also need the message hidden, combine HMAC with encryption, or use an AEAD cipher that does both.
  • Runs locally. The key and message stay in your browser — nothing is uploaded — so it's safe to test with real values.

Frequently Asked Questions

What's the difference between HMAC and a plain hash?
A plain hash (SHA-256) proves only that data wasn't changed, and anyone can recompute it. HMAC mixes in a secret key, so only someone with the key can produce or verify a valid tag. That's what lets it authenticate the sender, not just detect accidental changes.
Is HMAC-SHA1 still safe to use?
Yes, HMAC-SHA-1 itself is not broken — HMAC's security doesn't depend on SHA-1's collision resistance, which is the part that's weak. It's still used in many systems. For new designs, prefer HMAC-SHA-256, but you don't need to panic if you see HMAC-SHA-1.
How should I compare HMACs when verifying?
In code, use a constant-time comparison such as crypto.timingSafeEqual (Node) or hmac.compare_digest (Python). A normal equality check can leak timing information that helps an attacker forge a tag byte by byte. This tool's on-screen comparison runs locally, so the concern is about your server-side verifier.
Does HMAC encrypt my message?
No. HMAC authenticates a message but doesn't hide it. The message is sent in the clear with its tag attached. If you need confidentiality too, encrypt the message as well, or use an AEAD cipher like AES-GCM or ChaCha20-Poly1305 that provides both.
What makes a good HMAC key?
A long, random secret — ideally at least the hash's output size, so 32 bytes for SHA-256. Random bytes stored as hex or Base64 are better than a human-chosen word. HMAC's strength depends on the key staying secret and having enough entropy.
