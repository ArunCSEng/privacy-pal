What a Hash Is

A cryptographic hash turns any input — a word, a document, a multi-gigabyte file — into a fixed-length fingerprint. The same input always gives the same hash, and changing a single bit changes the output completely, so hashes are how you tell whether two things are identical without comparing them byte by byte. This tool computes five hashes (MD5, SHA-1, SHA-256, SHA-384, SHA-512) at once, for pasted text or a dropped file, and can check a value against an expected one.

A hash is one-way: you can't reverse it to recover the input. It is not encryption (there's no key and nothing to decrypt) and, on its own, it is not how you should store passwords — that needs a deliberately slow function like Argon2 or bcrypt, not a fast general-purpose hash.

Which Algorithm Is Safe — and Which Isn't

AlgorithmStatusUse for
SHA-256 / 384 / 512Secure (SHA-2)Everything security-related: integrity, signatures, fingerprints
SHA-1Broken (collisions demonstrated, 2017)Legacy interop only — never new security use
MD5Broken (collisions trivial)Non-security checksums — detecting accidental corruption only

This matters. MD5 and SHA-1 are still everywhere — ETags, legacy checksums, old file manifests — and they're perfectly fine for spotting accidental corruption, where no attacker is involved. But an attacker can craft two different files with the same MD5 or SHA-1, so never rely on them to prove a file hasn't been tampered with. For anything an adversary could target, use SHA-256 or stronger.

Verifying a Download — and What It Proves

The common use is checking a downloaded file against the checksum a project publishes. Drop the file in, paste the expected hash, and the tool highlights the matching algorithm. A match means the file is byte-for-byte what produced that hash — it caught any truncation or corruption in transit.

Be clear on what it doesn't prove: if the checksum came from the same page as the download, an attacker who replaced the file could have replaced the checksum too. A hash verifies integrity against accidents and against a checksum you obtained through a trusted channel; proving a file genuinely came from its author needs a digital signature (for example a GPG-signed checksum), not a bare hash.

How to Use the Tool

  1. Choose text or file. Type or paste text, or drop a file — large files are hashed locally in chunks.
  2. Read the five hashes, each with a copy button.
  3. Verify by pasting an expected checksum; the tool tells you which algorithm it matches.
  4. Prefer SHA-256+ for any security decision; treat an MD5 or SHA-1 match as a corruption check only.

Scope and Limits

  • Hashing isn't password storage. For passwords use Argon2, bcrypt or scrypt — slow by design — not these fast hashes.
  • MD5/SHA-1 are for non-adversarial checks only. Fine for detecting corruption, unsafe against tampering.
  • A checksum alone isn't authenticity. Combine it with a signature or a trusted source to prove origin.
  • Runs locally. Text and files are hashed in your browser — nothing is uploaded — so it's safe for private or large files.

Frequently Asked Questions

Is it safe to still use MD5 or SHA-1?
Only for non-security checks like detecting accidental file corruption. Both are broken against a deliberate attacker, who can create two different files with the same MD5 or SHA-1 hash. For anything security-related — integrity against tampering, signatures — use SHA-256 or stronger.
Can I recover the original text from a hash?
No. Hashing is one-way by design. For short or common inputs an attacker can guess-and-check (which is why passwords need a slow, salted function), but the hash itself contains no reversible copy of the input.
Does a matching checksum mean the file is genuine?
It means the file matches that checksum exactly, so it wasn't corrupted. It only proves authenticity if you got the checksum from a trusted source the attacker couldn't also change. To prove origin, use a digital signature such as a GPG-signed checksum.
Which hash should I use for a file fingerprint?
SHA-256 is the standard choice — secure, widely supported and fast enough. Use SHA-512 if you specifically want a longer digest. Reserve MD5 and SHA-1 for compatibility with systems that still require them, and only for non-security purposes.
Are my files uploaded to compute the hash?
No. All hashing runs in your browser, with the SHA family handled by the Web Crypto API and MD5 computed locally. Nothing you paste or drop is sent anywhere, so it's safe to hash private or large files.
