How Argon2 Key Derivation Operates

Argon2 (defined in RFC 9106) was the winner of the Password Hashing Competition (PHC) in 2015. It is designed to withstand both brute-force cracking on specialized hardware (GPUs/ASICs) and cache-timing side-channel attacks by operating on a large, memory-hard matrix of 1024-byte blocks:

  • Argon2d (Data-Dependent): Accesses memory in a pattern determined by the secret password. Provides the strongest resistance against GPU-assisted brute-force cracking, but can be vulnerable to cache-timing attacks in shared hardware environments.
  • Argon2i (Data-Independent): Accesses memory in a predefined pattern independent of secret data, eliminating side-channel leakage. Ideal for password hashing and authentication backends where timing attacks are an adversary model.
  • Argon2id (Hybrid Baseline): The primary recommended modern variant. Uses data-independent addressing for the first pass over memory to resist side channels, followed by data-dependent addressing for subsequent passes to maximize GPU attack resistance.

Recommended Baseline Parameters

For password hashing, RFC 9106 recommends starting with a minimum memory cost of 19 MiB ($m=19456$) with 2 iterations ($t=2$) or 64 MiB ($m=65536$) with 1 iteration ($t=1$) where hardware allows. In client-side browser environments, memory costs between 2048 KiB and 16384 KiB ensure seamless execution across lower-powered mobile engines without freezing thread runtimes.
