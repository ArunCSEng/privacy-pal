PEM and DER Are the Same Bytes, Packaged Differently

A certificate or key has one canonical binary form: DER, the raw ASN.1 encoding. PEM is just that DER wrapped for text: the bytes are Base64-encoded, split into 64-character lines, and bracketed with -----BEGIN LABEL----- and -----END LABEL-----. Converting between them doesn't change, decrypt or re-sign anything — it only re-packages the identical bytes. This tool converts each way in your browser and shows the DER size, its SHA-256 and the leading ASN.1 tag.

Why You'd Convert

Different ecosystems expect different packaging. OpenSSL, Apache and nginx usually want PEM (.pem, .crt, .key); many Windows and Java tools expect DER (.der, .cer). When a tool rejects a file, the contents are often fine and only the encoding is wrong — converting is the fix.

The Label Has to Be Right

Going from DER to PEM, you choose the label, and it must match what the bytes actually are:

LabelContents
CERTIFICATEAn X.509 certificate
PUBLIC KEYA SubjectPublicKeyInfo public key
PRIVATE KEYA PKCS#8 private key
CERTIFICATE REQUESTA PKCS#10 CSR
EC PRIVATE KEY / RSA PRIVATE KEYOlder key-specific formats

The wrong label produces a PEM block that looks valid but that tools will reject, because the header claims one thing and the bytes are another. The leading tag the tool reports is a quick sanity check: certificates, keys and CSRs all start with 0x30 (ASN.1 SEQUENCE).

A Worked Example You Can Verify

Conversion is lossless, which you can confirm with OpenSSL. For a certificate cert.pem: 

openssl x509 -in cert.pem -outform DER -out cert.der
openssl x509 -inform DER -in cert.der -out roundtrip.pem

The cert.der that OpenSSL writes is byte-for-byte what this tool produces from the same PEM, and its SHA-256 matches the tool's reported hash (openssl dgst -sha256 cert.der). Convert back and the PEM body is identical. That stable hash is the proof the conversion changed packaging only, not content.

Private Keys: Safe Here, but Be Careful in General

This converter handles private keys as well as certificates, and because everything runs in your browser with nothing uploaded, that's safe. The wider habit matters, though: never paste a production private key into an online converter you don't control. The offline equivalent is a one-line OpenSSL command. Note too that conversion doesn't remove a passphrase — an encrypted PEM key converts to encrypted DER and stays encrypted; decrypting is a separate step.

Frequently Asked Questions

What's the actual difference between PEM and DER?
DER is the raw binary ASN.1 encoding. PEM is the same bytes Base64-encoded, wrapped at 64 characters, with BEGIN/END header lines. They contain identical data — PEM is just the text-friendly packaging of DER.
Does converting change or weaken my certificate or key?
No. Conversion only re-encodes the same bytes, so the certificate or key is unchanged. You can confirm this: the SHA-256 of the DER is the same before and after a round trip through PEM.
Is it safe to convert a private key here?
In this tool, yes — it runs entirely in your browser and uploads nothing. As a general rule, though, don't paste production private keys into online tools you don't control. The offline equivalent is a single OpenSSL command.
Which label should I choose for DER to PEM?
Match the label to the contents: CERTIFICATE for an X.509 cert, PRIVATE KEY for a PKCS#8 key, PUBLIC KEY for a public key, CERTIFICATE REQUEST for a CSR. The wrong label makes a block that looks valid but that tools reject.
My key is passphrase-protected — will converting remove it?
No. An encrypted PEM key converts to encrypted DER and remains encrypted. Removing or changing a passphrase is a separate operation (for example with OpenSSL), not something format conversion does.
