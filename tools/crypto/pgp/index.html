What This PGP Tool Does

PGP (via the OpenPGP standard) is how you encrypt a message so that only the intended recipient can read it. This tool does three things in your browser, using the established OpenPGP.js library: generate a key pair, encrypt a message, and decrypt one. It works with standard ASCII-armored blocks — the -----BEGIN PGP …----- text you can paste into email or chat — so its output interoperates with GnuPG and other OpenPGP software.

The Public-Key Model

Each person has a public key they share freely and a private key they keep secret, usually protected by a passphrase. To send someone a message, you encrypt it to their public key; only their private key can decrypt it. The two never swap roles: publishing your public key lets anyone write to you, but only you can read what comes back.

The tool also offers a symmetric mode: instead of keys, both sides share one passphrase. That's handy for a quick password-protected message, but it carries the usual shared-secret problem — you need a safe way to deliver the passphrase, and anyone who has it can read the message.

Encrypting Proves Secrecy, Not Who Sent It

An important point about what you get back. This tool encrypts and decrypts, but it does not add or check a digital signature. So a successful decryption proves the message was encrypted to your key and wasn't readable in transit — it does not prove who sent it. Full PGP workflows also sign messages, which is what authenticates the sender and detects tampering. If you need that assurance, sign and verify with a dedicated client such as GnuPG; treat a clean decryption here as confidentiality only.

Choosing a Key Type

RSA 2048Legacy compatibility; adequate but no reason to prefer it for new keys

Always set a passphrase when generating a key for anything real — it's what protects the private key if the file is ever exposed.

A Worked Example You Can Reproduce

The round trip is the thing to try:

  1. Generate a key pair (Ed25519, with a passphrase). You get a public and a private armored block.
  2. Encrypt a test message to that public key. The output is a PGP MESSAGE block, and it looks completely different each time — PGP uses a fresh random session key per message.
  3. Decrypt that block with the private key and passphrase, and the original text comes back.

Because the ciphertext is randomised, there's no fixed value to match — but the armored message this tool produces decrypts correctly in GnuPG with the same key, and vice versa, which is the real test of OpenPGP compatibility.

How to Use the Tool

  1. Key generation: enter a name, email and passphrase, pick a type, and generate. Save both blocks; the private key cannot be recovered if lost.
  2. Encrypt: paste the recipient's public key (or a passphrase for symmetric mode) and your message, and copy the armored result.
  3. Decrypt: paste the armored message plus your private key and its passphrase (or the shared passphrase), and read the plaintext.

Using PGP Keys Safely

  • Great for learning and test or throwaway keys. For a real, long-term identity key, generate and store it with an offline client like GnuPG rather than any website.
  • Never paste a real long-term private key into a web tool you don't control. This one runs locally and uploads nothing, but that caution is the right habit everywhere.
  • Protect private keys with a strong passphrase and keep a secure backup; there's no reset.
  • For sender authentication, use signing in a full client — this tool provides encryption and decryption only.

Frequently Asked Questions

Which key do I share, and which do I keep?
Share your public key — it's what others use to encrypt messages to you. Keep your private key secret and passphrase-protected; it's the only thing that can decrypt those messages. Never send the private key to anyone.
Does a successful decryption prove who sent the message?
No. Decryption proves the message was encrypted to your key and stayed secret in transit. It does not authenticate the sender — that requires a digital signature, which this tool doesn't create or verify. Use a client like GnuPG when you need to sign and verify.
Should I generate my real PGP key here?
For learning or a throwaway key, this is fine and runs entirely in your browser. For a long-term identity key, generate and store it with an offline tool like GnuPG, and never paste an existing real private key into a website you don't control.
What's the difference between key mode and passphrase mode?
Key mode uses public-key cryptography: encrypt to someone's public key, they decrypt with their private key. Passphrase (symmetric) mode uses one shared secret for both sides — simpler, but you must deliver the passphrase securely and anyone who has it can read the message.
Which key type should I choose?
Ed25519 (Curve25519) is the modern default — fast and secure with small keys. Choose RSA 4096 only if you must interoperate with older software that doesn't support elliptic-curve keys. RSA 2048 is legacy; there's little reason to pick it for a new key.
