What This Tool Generates

RSA is public-key cryptography: a key pair where the public key is shared and the private key is kept secret. This tool generates a pair in your browser with the Web Crypto API, exports the public key as SPKI PEM and the private key as PKCS#8 PEM, shows a SHA-256 fingerprint of the public key, and can download both as a JWK set. The output is standard, so the keys work with OpenSSL, Java, Node and other tooling.

Pick the Purpose: Encryption or Signing

An RSA key is generated for one job, and the tool makes you choose:

  • RSA-OAEP — for encryption and decryption. OAEP is the modern padding scheme; it replaces the old PKCS#1 v1.5 encryption padding that had padding-oracle weaknesses.
  • RSA-PSS — for digital signatures. PSS is the modern, randomised signature scheme, preferred over legacy PKCS#1 v1.5 signatures.

Choosing OAEP or PSS here isn't cosmetic — a key marked for encryption can't be used to sign, and vice versa. Both options are the current best-practice schemes, so you don't need to second-guess the padding.

The public exponent is fixed at 65537, the standard choice. Bigger keys are slower to generate and to use, with diminishing returns — 3072 is the sensible default for a new key that needs to last, and 2048 remains acceptable for near-term compatibility.

A Worked Example You Can Verify

Generate a pair and the public key is a real, standards-compliant RSA key. You can confirm it with OpenSSL: 

openssl pkey -pubin -in public.pem -noout -text     # shows the bit length and 65537 exponent
openssl pkey -pubin -in public.pem -outform DER | openssl dgst -sha256

That SHA-256 value matches the fingerprint the tool displays, because the fingerprint is simply the hash of the public key's DER encoding. The private PEM loads with openssl pkey -in private.pem and pairs with the public key — which is how you'd verify any generated key is genuine.

RSA or Elliptic Curve?

RSA is everywhere and maximally compatible, but its keys are large and operations are comparatively slow. For new systems, elliptic-curve keys (Ed25519 for signatures, X25519 for key exchange) give equivalent security with far smaller keys and better performance. Generate RSA when you need it for compatibility with existing systems; reach for a curve-based key when you're free to choose.

Frequently Asked Questions

Should I pick RSA-OAEP or RSA-PSS?
RSA-OAEP if the key is for encrypting and decrypting data; RSA-PSS if it's for signing and verifying. A key is bound to one purpose, so choose based on what you'll do with it. Both are the modern, padded schemes, so either is a safe choice for its job.
What key size should I use?
2048-bit is the current minimum and fine for near-term use; 3072-bit is NIST's recommended baseline for keys that need to last, giving about 128-bit security; 4096-bit adds margin at a speed cost. For a new long-lived key, 3072 is a sensible default.
Is the downloaded private key protected?
No. It's exported as unencrypted PKCS#8, so anyone with the file has the key. Encrypt it before storing (for example with openssl pkcs8 -topk8) or keep it in a secrets manager, and never commit it to source control.
Why might I choose elliptic curve instead of RSA?
Elliptic-curve keys (like Ed25519) offer the same security as much larger RSA keys, with smaller sizes and faster operations. RSA is still widely required for compatibility, so generate it when you need it — but for new designs that are free to choose, a curve-based key is often better.
Are my keys sent anywhere?
No. Key generation runs entirely in your browser with the Web Crypto API, and nothing is uploaded. Even so, treat the private key as sensitive from the moment it's created and store it securely.
