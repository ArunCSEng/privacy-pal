How AES-GCM Authenticated Encryption Works

AES-GCM (Galois/Counter Mode) combines standard counter mode (CTR) symmetric encryption with Galois field polynomial multiplication (GHASH) to provide both confidentiality and message integrity simultaneously:

  • Confidentiality via CTR: AES encrypts successive increments of the counter initial state derived from the IV to form a continuous keystream, XORing it with the plaintext.
  • Authenticity & Integrity via GHASH: As ciphertext blocks are computed, they are authenticated over a Galois field ($GF(2^{128})$) using a subkey derived from the master secret.
  • Additional Authenticated Data (AAD): GCM allows arbitrary unencrypted metadata (such as IP headers or transaction identifiers) to be bound to the authentication tag without being encrypted. If an attacker modifies the AAD or ciphertext in transit, authentication immediately fails upon decryption.

Critical Nonce Separation Rules

The standard GCM construction requires a unique 96-bit (12-byte) initialization vector for every single encryption operation performed under a given secret key. Reusing a nonce produces identical keystreams, permitting XOR ciphertext-stripping attacks and allowing forgery of GHASH authentication tags.
