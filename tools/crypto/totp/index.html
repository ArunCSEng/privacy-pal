How One-Time Password Algorithms Operate

Two-factor authentication tokens generated by apps like Google Authenticator, Bitwarden, or hardware security keys rely on open RFC standards:

  • HOTP (RFC 4226): An HMAC-based One-Time Password derived from a shared secret $K$ and an incrementing 64-bit integer counter $C$:

$$\text{HOTP}(K, C) = \text{Truncate}(\text{HMAC-SHA-1}(K, C)) \pmod{10^{\text{digits}}}$$

  • TOTP (RFC 6238): A time-based extension where the moving counter $C$ is computed dynamically from Unix epoch time $T$ divided by a time step window $X$ (standard 30 seconds):

$$C = \left\lfloor \frac{T - T_0}{X} \right\rfloor$$

Dynamic Truncation Scheme

The output of the HMAC digest (20 bytes for SHA-1, 32 for SHA-256) is truncated using the lower 4 bits of the last byte as an offset index (ranging from 0 to 15). A 31-bit unsigned big-endian integer is extracted from the 4 bytes starting at that offset, masked with 0x7FFFFFFF, and modulo reduced to produce the final 6 or 8-digit token string.

Zero Network Egress Security Guarantee

Secrets evaluated in this tool remain isolated in client memory. All HMAC calculations utilize the Web Cryptography API (crypto.subtle), preventing unauthorized data extraction, logs, or analytics.
