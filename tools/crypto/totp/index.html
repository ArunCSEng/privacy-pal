What TOTP and HOTP Are

These are the one-time codes two-factor authentication relies on — the six digits an app like Google Authenticator shows, rotating every 30 seconds. Both come from the same idea: the server and your device share a secret, and each computes an HMAC of that secret combined with a moving value, then truncates it to a short code. TOTP (RFC 6238) uses the current time as the moving value; HOTP (RFC 4226) uses a counter that steps on each use. This tool generates both in your browser.

How a Code Is Produced

  1. Decode the Base32 secret into bytes — the shared key.
  2. Pick the moving factor: for TOTP, the number of time steps since 1970 (seconds ÷ step); for HOTP, the counter.
  3. HMAC the 8-byte factor with the secret, then apply RFC 4226 "dynamic truncation" to pull a number out of the hash and take the last 6 (or 8) digits.

Because both sides run the same steps on the same secret, they arrive at the same code without ever sending it. A small clock difference is handled by the server checking the adjacent time windows too.

A Worked Example You Can Reproduce

The RFC test vectors use the Base32 secret GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ (the ASCII string "12345678901234567890"): 

HOTP (SHA-1, 6 digits):  counter 0 → 755224   counter 1 → 287082
TOTP (SHA-1, 8 digits):  at Unix time 59s   → 94287082

Matching a Real Authenticator App

One practical point that trips people up: common authenticator apps (Google Authenticator and most others) only support SHA-1, 6 digits, and a 30-second step. The RFC allows SHA-256, SHA-512 and 8 digits, and this tool offers them, but if you choose those settings the codes won't match what a standard app shows. Keep the defaults (SHA-1 / 6 digits / 30s) when your goal is to match an app; change them only when the service you're integrating with explicitly uses different parameters.

Frequently Asked Questions

What's the difference between TOTP and HOTP?
Both HMAC a shared secret with a moving value. TOTP uses the current time divided into fixed steps (usually 30 seconds), so codes rotate on a clock. HOTP uses a counter that advances each time a code is used. TOTP is what most authenticator apps use; HOTP appears in some hardware tokens.
Why doesn't my code match Google Authenticator?
Almost certainly the parameters. Standard apps use SHA-1, 6 digits and a 30-second step. If you selected SHA-256, SHA-512 or 8 digits here, the codes will differ. Switch back to SHA-1 / 6 digits / 30s to match an app, and double-check the Base32 secret is entered exactly.
Is it safe to enter my real 2FA secret?
In this tool it runs entirely in your browser and nothing is uploaded, so it's safe for testing. As a rule, though, don't paste a live 2FA secret into online tools you don't control — the secret is the whole second factor, and anyone who has it can generate your codes.
Why is there a short time window on each code?
TOTP codes are valid only for their time step (typically 30 seconds) so a code glimpsed or intercepted is useless moments later. Servers usually also accept the immediately previous and next window to tolerate small clock differences between devices.
Can I import a 2FA QR code?
You can paste the otpauth:// URI that a QR code encodes, and the tool will read the secret, algorithm, digit count and period from it. That's the same data the QR image contains, just in text form.
