What an SSH Fingerprint Is

An SSH key fingerprint is a short hash of a public key that stands in for the whole key when you need to recognise it. It's the value in the The authenticity of host '…' can't be established … key fingerprint is SHA256:… prompt you see on a first connection, and it's how you confirm an entry in an authorized_keys file is the key you think it is. This tool takes a public key and produces its fingerprints in your browser.

Two Formats: SHA256 and MD5

FormatLooks likeStatus
SHA256SHA256:4cIZJLDHLKi5… (Base64)Current OpenSSH default — use this
MD5MD5:f9:aa:d2:6d:… (hex pairs)Legacy — for matching older systems and logs only

OpenSSH switched its default to the SHA256 form years ago; the MD5 form appears in older documentation, device output and logs, which is why the tool shows both. Compare like with like — a SHA256 fingerprint only matches another SHA256 fingerprint.

A Worked Example You Can Verify

The fingerprints are exactly what ssh-keygen produces, because they're computed the same way — a hash of the key's binary blob. For a public key file: 

ssh-keygen -lf key.pub            # the SHA256:… fingerprint
ssh-keygen -E md5 -lf key.pub     # the MD5:… fingerprint

Load the built-in Ed25519 sample and the tool shows SHA256:4cIZJLDHLKi51KIuoBRtXhoB64LM36q0ySgBWdViHiw and MD5:f9:aa:d2:6d:57:e4:33:dd:03:38:7e:67:a2:b1:29:bf — the same values those commands give for that key. The SHA256 form is the Base64 of the SHA-256 hash with padding removed; the MD5 form is the hash as colon-separated hex.

What a Fingerprint Is — and Isn't — Good For

A fingerprint lets you recognise a key, but only helps if you compare it against a value you got through a trusted channel:

  • Verifying a server on first connect. The fingerprint is only meaningful if you check it against one the server's operator published, not the one the server itself just offered. Accepting whatever appears ("trust on first use") skips the actual verification.
  • Auditing authorized keys. Fingerprint each entry to match it against a roster of keys you expect, and spot ones you don't.
  • Confirming two copies match. Same key, same fingerprint — a quick way to check a key wasn't altered in transit.

A fingerprint is derived from the public key, so it isn't secret and is safe to publish. Prefer the SHA256 form; while a matching MD5 fingerprint is still a useful identity check in practice, MD5 is weak and shouldn't be relied on where an attacker could craft a colliding key.

Frequently Asked Questions

Why are there two fingerprints for one key?
They're the same key hashed two ways. SHA256 (Base64) is the modern OpenSSH default; MD5 (colon-separated hex) is the older format still seen in legacy tools and logs. Use SHA256, and only fall back to MD5 to match something that reports it.
Does this match ssh-keygen?
Yes. The fingerprints are computed the same way ssh-keygen computes them — a hash of the key's binary blob — so they match "ssh-keygen -lf" (SHA256) and "ssh-keygen -E md5 -lf" (MD5) for the same key.
Is it safe to share a key's fingerprint?
Yes. A fingerprint is derived from the public key, which is already shareable, and it can't be reversed into the key. Publishing a server's SHA256 fingerprint is in fact how operators let users verify a first connection.
Is the MD5 fingerprint still trustworthy?
For simply recognising a key you already know, a matching MD5 fingerprint is a reasonable check. But MD5 is cryptographically broken, so don't rely on it where an attacker could deliberately craft a key with a colliding fingerprint. Prefer SHA256.
Can I paste my private key to fingerprint it?
No — paste only the public key (the .pub file or the authorized_keys line). Fingerprints are made from public keys, and a private key should never be entered into any online or third-party tool. This tool runs locally and uploads nothing, but the rule stands everywhere.
