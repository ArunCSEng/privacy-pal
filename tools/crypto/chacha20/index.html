What ChaCha20-Poly1305 Is

ChaCha20-Poly1305 is an authenticated encryption cipher (AEAD): it encrypts data with the ChaCha20 stream cipher and authenticates it with the Poly1305 MAC, so the output is both confidential and tamper-evident. It's the IETF construction from RFC 8439, and it's what TLS 1.3, WireGuard and modern SSH use as a fast alternative to AES-GCM — especially on devices without AES hardware acceleration, where ChaCha20 stays quick and runs in constant time. This tool implements RFC 8439 directly in your browser.

The Inputs

FieldMeaning
Key256-bit (32-byte) secret. The only secret; both sides need the same one
Nonce96-bit (12-byte) value per message. Not secret, but must be unique for a given key
AADAssociated data that is authenticated but not encrypted — e.g. a header or version
TagThe 128-bit Poly1305 tag that proves the ciphertext and AAD weren't altered

On encryption the tool returns the ciphertext and a separate 128-bit tag; on decryption it recomputes the tag and only returns plaintext if it matches, so a wrong key, wrong nonce, mismatched AAD or altered ciphertext fails cleanly.

The One Rule That Matters Most: Never Reuse a Nonce

Like every AEAD built on a stream cipher, ChaCha20-Poly1305 is only secure if each message under a given key uses a unique nonce. Reusing the same key-and-nonce pair for two messages produces the same keystream, which leaks the XOR of the two plaintexts and undermines the Poly1305 authentication. The nonce isn't secret — you can send it with the ciphertext — but it must never repeat under the same key. That's why this tool generates a fresh random 96-bit nonce for each encryption.

How the Authentication Works

The Poly1305 one-time key is derived by running ChaCha20 once with the counter set to zero and taking the first 32 bytes of keystream; encryption of the message then starts from counter one. The tag is computed over the AAD and the ciphertext, each padded to a 16-byte boundary, followed by their lengths. This binds the tag to both the data and the context, which is what makes AEAD stronger than encrypt-then-hope.

How to Use the Tool

  1. Encrypt: generate or paste a 32-byte key, let the tool generate a fresh nonce, add optional AAD, enter your plaintext, and run. Keep the key, nonce and tag together to decrypt later.
  2. Decrypt: switch to decrypt, supply the hex ciphertext, the matching key, nonce, AAD and the 16-byte tag. A failed tag check reports an authentication error instead of returning wrong plaintext.
  3. Experiment with AAD to see that changing it — on either side — makes verification fail, which is the point of associated data.

Frequently Asked Questions

ChaCha20-Poly1305 or AES-GCM — which should I use?
Both are strong modern AEADs. AES-GCM is usually faster where the CPU has AES hardware; ChaCha20-Poly1305 is faster in pure software and on mobile, and runs in constant time. TLS 1.3 negotiates whichever fits. For new software without guaranteed AES acceleration, ChaCha20-Poly1305 is a safe default.
Why must the nonce be unique for each message?
Reusing a key-and-nonce pair repeats the keystream, which leaks the XOR of the two plaintexts and weakens the authentication. The nonce isn't secret, but it must never repeat under the same key. This tool generates a fresh random 96-bit nonce each time for that reason.
What's the difference between AAD and plaintext?
Plaintext is encrypted and authenticated. Associated data is authenticated but left in the clear — for context like a header or message ID you want bound to the ciphertext so it can't be swapped. Decryption fails if the AAD doesn't match.
What does an authentication failure on decryption mean?
The Poly1305 tag didn't verify, so no plaintext is returned. The cause is a wrong key, wrong or mismatched nonce, mismatched AAD, or altered ciphertext. It's working as intended — tampered or mis-keyed data is rejected rather than silently decrypted.
Is this interoperable with other libraries?
Yes. It implements RFC 8439 and matches the specification's test vector exactly, so its ciphertext and tag interoperate with libsodium, OpenSSL and other correct implementations given the same key, nonce and AAD.
