How PBKDF2 Operates

Password-Based Key Derivation Function 2 (PBKDF2), standardized under RFC 8018 and RFC 2898, applies a pseudorandom function (PRF)—most commonly an HMAC variant—to a secret password along with a cryptographic salt across thousands of iterative cycles:

  • Formula: $DK = \text{PBKDF2}(PRF, \text{Password}, \text{Salt}, c, dkLen)$ where $c$ is the iteration count and $dkLen$ is the target key length in octets.
  • Salt Separation: Salts defeat precomputed dictionary attacks (rainbow tables) by guaranteeing that identical passwords produce completely distinct derived keys across systems.
  • Cost Amplification: Each iteration feeds the previous block output back through the HMAC routine, increasing the computational threshold necessary for attackers attempting offline brute-force cracking.

Recommended Iteration Guidelines

OWASP recommends a minimum baseline of 600,000 iterations for PBKDF2-HMAC-SHA-256 and 210,000 iterations for PBKDF2-HMAC-SHA-512 as of standard defense baselines. When deriving symmetric keys inside client-side browser runtimes, iterations between 100,000 and 600,000 offer high security margins without freezing UI threads.
