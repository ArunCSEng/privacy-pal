⚠️ Limitations & Disclaimer

Invisible characters aren't always malicious, and this tool doesn't find every kind. Emoji, Persian and right-to-left text use some of them legitimately, and stripping can break that text. Directional isolates, Unicode tag characters and variation selectors aren't detected. Results are provided as-is; BitDark.net is not liable for decisions made using them.

Why Invisible Characters Matter

Unicode includes characters that take up no visible space: zero-width spaces and joiners, direction marks, soft hyphens and more. They have legitimate jobs, but they can also hide things in text that looks normal:

  • Filter evasion. "Ig[ZWSP]nore" with a zero-width space inside no longer matches a keyword filter, though a person or a language model may still read it as "Ignore".
  • Hidden messages and watermarks. Sequences of two different zero-width characters can encode bits, for example to fingerprint which copy of a document leaked.
  • Misleading display. Right-to-left override characters reverse how text is shown. invoice_[RLO]fdp.exe displays as "invoice_exe.pdf". The 2021 "Trojan Source" research (CVE-2021-42574) used direction controls to make source code look different from what the compiler sees.

How to Use the Zero-Width Detector

  1. Paste the text, for example an untrusted prompt, a copied document or a code snippet. Markers appear on the right as you type.
  2. Check where each marker sits. A ZWJ between emoji, or a ZWNJ inside a Persian word, is normal. Zero-width characters between the letters of an English word are not.
  3. Try Extract Hidden Payload if you see long runs of ZWSP and ZWNJ.
  4. Strip only when the text is plain English or code. Removing joiners breaks emoji and changes spelling in some languages.

Other Invisible Characters to Watch

  • Directional isolates (U+2066–U+2069): used in Trojan Source attacks alongside overrides. Many code editors and GitHub now warn about them.
  • Unicode tag characters (U+E0000–U+E007F): invisible copies of ASCII letters that can carry whole hidden sentences, including prompt-injection instructions that some language models will read.
  • Variation selectors (U+FE00–U+FE0F, U+E0100–U+E01EF): normally change how an emoji or character looks, but long runs of them can encode hidden data.
  • Lookalike blanks such as the Hangul filler (U+3164) and braille blank (U+2800), which display as empty space.

For systems that accept untrusted text, normalise input (Unicode NFKC) and remove or reject format characters you don't expect, while allowing the joiners that your users' languages and emoji need.

Frequently Asked Questions

Are zero-width characters always malicious?
No. The zero-width joiner builds emoji like 👨‍👩‍👧, the non-joiner is part of normal Persian spelling, and direction marks are needed for Arabic and Hebrew. They're suspicious when they appear inside English words or code where they have no purpose.
Will stripping invisible characters break my text?
It can. Stripping removes the joiners inside combined emoji, so a family emoji becomes three separate people, and it changes the spelling of words in languages that use ZWNJ. It's safe for plain English text and most source code.
How does Extract Hidden Payload work?
It treats each zero-width space (U+200B) as 0 and each zero-width non-joiner (U+200C) as 1, takes the bits in groups of 8, and shows the resulting characters. The built-in preset decodes to "PWN". Messages hidden with other characters or encodings won't decode this way.
Does it detect Unicode tag characters or Trojan Source isolates?
No. It covers 13 common characters, including the right-to-left override, but not the directional isolates U+2066–U+2069, the tag characters U+E0000–U+E007F or variation selectors. Text using those shows as clean.
Is my text uploaded?
No. Scanning, stripping and decoding all run in JavaScript in your browser, and the tool makes no network requests with your text.
