What a Model Card Is

A model card is the documentation that ships with a machine-learning model. It says what the model is, what it's for, what it was trained on, how well it performs and where it fails. The idea comes from the 2019 paper Model Cards for Model Reporting by Margaret Mitchell and colleagues. On Hugging Face, a model card is the repository's README.md: YAML metadata at the top (license, language, datasets, base model, tags) followed by Markdown sections.

What This Linter Checks

The linter runs 10 checks. Each one passes if any of its keywords appears anywhere in the text (case-insensitive). The score is the percentage of checks that pass.

Keywords are matched inside longer words too. Most importantly, "mit" matches "limitations" and "submitted", so almost any card with a Limitations section passes the license check, even with no license. Check the license line yourself.

How to Use the Model Card Linter

  1. Paste your model card, including the YAML frontmatter, into the editor. Results update as you type.
  2. Fix the red items first. They're the five sections most readers and reviewers look for.
  3. Read each passing section anyway. A green tick means a keyword was found, not that the section says anything useful.
  4. Export the result with "Export Audit Report (JSON)" to attach it to a pull request or review.

Writing a Card That's Actually Useful

  • Put the license in the metadata (license: apache-2.0, for example) and name the base model if it's a fine-tune. Hugging Face uses these fields for search and filtering.
  • Be specific about use. Say who the model is for and give concrete out-of-scope cases, not "do not misuse".
  • Link the data. Name the datasets or describe the sources and filtering, so others can judge coverage and licensing.
  • Report numbers with context. Give the benchmark, split and metric, and how the result compares with the base model.
  • Describe failure modes you've seen, including languages, groups or inputs where the model does worse.
  • Give a contact for questions and security reports.

A model card isn't legal compliance on its own. For example, the EU AI Act requires providers of general-purpose AI models to keep technical documentation and publish a summary of training content. A good model card supports that work but doesn't replace it.

Frequently Asked Questions

Does a 100% score mean my model card is complete?
No. Each check only looks for a keyword, so a single line of the right words scores 100%. Use the results to find missing sections, then read each section to make sure it says something specific.
Why does the license check pass when my card has no license?
The check accepts "mit" anywhere in the text, including inside words like "limitations" and "submitted". Add an explicit license field to your YAML metadata, such as license: apache-2.0, and confirm it yourself.
Which sections does Hugging Face expect in a model card?
Hugging Face's template covers model details, uses (direct, downstream and out-of-scope), bias, risks and limitations, training details, evaluation, environmental impact and contact, plus YAML metadata such as license, language, datasets and base model.
Does the linter read the YAML metadata separately?
No. It searches the whole pasted text as one block, so YAML fields and Markdown headings count the same way. It doesn't check that metadata values are valid, for example that a license identifier exists.
Is my model card uploaded?
No. The checks run in JavaScript in your browser, and the tool makes no network requests with your text. The exported report is created locally.
