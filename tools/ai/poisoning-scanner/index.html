What Data Poisoning Is

Data poisoning means tampering with training data so a model learns the wrong thing. The common forms are:

  • Label flipping: correct examples are given the wrong label, for example spam marked as safe.
  • Backdoors (triggers): examples containing a rare token or phrase are all given the attacker's chosen label, so the trained model behaves normally until it sees that trigger.
  • Clean-label poisoning: examples look correct and keep plausible labels, but are crafted to shift the model's behaviour. These are very hard to spot by inspection.

The risk is real for language models too. A 2025 study by Anthropic, the UK AI Security Institute and the Alan Turing Institute found that around 250 poisoned documents were enough to plant a simple backdoor in models of every size they tested. OWASP lists data and model poisoning as LLM04 in its 2025 Top 10 for LLM applications.

How to Use the Dataset Poisoning Scanner

  1. Load a CSV, JSON or JSONL file, or paste a sample. For CSV, the last column is read as the label, and a first row containing "label", "target" or "class" is treated as a header. For JSON and JSONL, the text comes from text, prompt or input, and the label from label or y.
  2. Click "Audit Dataset".
  3. Read the JSON report. It lists each label conflict with both record numbers, and each trigger match with the matched token. Record numbers are line numbers, so with a CSV header the first data row is record 2.
  4. Review every hit by hand before deleting anything, then export the report if you need to keep it.

What a Real Dataset Audit Needs

  • Check provenance first. Know where each data source came from, and use checksums or signed releases for third-party datasets.
  • Find near-duplicates with fuzzy matching or embeddings, not just exact text.
  • Look at rare tokens per label. A backdoor trigger is usually a token that appears almost only with one label.
  • Test the trained model on held-out data and on inputs with suspected triggers added.
  • Expect clean-label attacks to need model-based methods, such as spectral or activation analysis, rather than a text scan.

Frequently Asked Questions

Does "Dataset Consistency Verified" mean my data is safe?
No. It means none of the three simple checks matched. Near-duplicates with different punctuation, unusual triggers and clean-label poisoning won't be found. Treat it as "nothing obvious", not as verification.
Why are ordinary words flagged as triggers?
One trigger pattern matches any 6 to 8 character word made only of digits and the letters a–f. That includes words like "decade", "facade" and "defaced", and numbers like dates, order IDs and short phone numbers. Check each match before treating it as an attack.
What is a label-flipping attack?
It's when an attacker changes the labels of some training examples so the model learns the wrong mapping. The scanner catches the simple case where the same text appears twice with different labels.
How many poisoned examples does it take to affect a model?
Fewer than many people expect. A 2025 study by Anthropic, the UK AI Security Institute and the Alan Turing Institute found that about 250 poisoned documents could plant a simple backdoor in language models of every size tested, regardless of how much clean data they were trained on.
Is my dataset uploaded?
No. Files are read with the browser's FileReader, all checks run in JavaScript in your tab, and the tool makes no network requests with your data. Very large files may be slow, depending on your device's memory.
