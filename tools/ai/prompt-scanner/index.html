What Prompt Injection Is

Prompt injection is when text an LLM reads changes what it does, against the developer's intent. It's number one (LLM01) in the OWASP Top 10 for LLM Applications 2025.

  • Direct injection comes from the user, for example "ignore your previous instructions".
  • Indirect injection hides in content the model processes, such as a web page, email, PDF or tool result, and can steer an agent without the user noticing.

Because language models follow instructions written in ordinary language, there's no complete list of attack phrases. A pattern scanner can catch common copy-paste attacks, but it can't make an application safe on its own.

Defences That Actually Work

  • Limit what the model can do. Give agents only the tools and permissions the task needs, and require human approval for actions such as sending email, payments or deletions.
  • Keep untrusted content separate. Mark retrieved documents and user input clearly as data, and don't let them change system-level settings.
  • Handle output carefully. Don't auto-render external Markdown images or links from model output, which can leak data through URL parameters. Validate any output before it reaches a shell, database or browser.
  • Strip or flag invisible characters, including Unicode tag characters, from untrusted input.
  • Test continuously. Red-team your application with paraphrased, multilingual and encoded attacks, not just known strings.

Frequently Asked Questions

Can this scanner stop prompt injection?
No. It matches a short list of English patterns, so rewording, translating or encoding an attack gets past it. In our test even one of its own presets scored 0. Use it to study common attacks and test examples, and rely on permissions, output handling and human approval for real protection.
Why did a harmless prompt get flagged?
Some patterns are broad. "Show instructions" matches the extraction rule and "research purposes" matches the hypothetical-framing rule, even in ordinary requests. Read the trigger text shown for each finding to judge whether it's a real attack.
What is indirect prompt injection?
It's an attack hidden in content the model reads rather than typed by the user, such as instructions in a web page, document, email or API response. It's especially risky for agents that browse, read files or call tools on the user's behalf.
Does it detect hidden Unicode characters?
Partly. It detects zero-width spaces and joiners, the byte-order mark and ASCII control characters. It doesn't detect Unicode tag characters (U+E0000 to U+E007F), which can hide whole sentences of invisible text, or other invisible characters such as the word joiner.
Is my prompt sent anywhere?
No. The rules run in JavaScript in your browser, and the tool makes no network requests with what you paste.
