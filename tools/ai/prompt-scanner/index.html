⚠️ Operational Guardrail Disclaimer & Limitations

Heuristic scanning is not a guarantee of safety. Large Language Models are stochastic, non-deterministic token engines. A "Clean (0 / 100)" verdict indicates that no known structural override strings, delimiter breaks, or signature jailbreaks matched our deterministic pattern database. It does not prove that a clever semantic rephrasing, polyglot encoding, or multi-turn conversational trick cannot bypass downstream model guardrails.

This utility is intended for initial local triage and CI/CD policy linting. Production agent systems should pair input scanning with parameterized delimiter boundaries (e.g., JSON schemas or XML encapsulations), strict privilege isolation (least-privilege tool execution), and independent output verification models.

How Client-Side Prompt Injection Scanning Operates

Large Language Model (LLM) agents combine developer system instructions and dynamic user strings into a single shared execution stream. Attackers exploit this architecture using prompt injection: crafting text that tricks the model into prioritizing hostile inputs over authorized system guardrails.

  • Instruction Override Attacks: Phrases like ignore all previous instructions or disregard prior commands attempt to reset the instruction context stack.
  • Role-Playing Exploits (DAN/Persona): Forcing the model into hypotheticals, unrestricted personas, or developer testing modes (e.g., "Do Anything Now" or "unfiltered debug console").
  • Delimiter Breakouts: Injecting pseudo-chat tokens (<|im_start|>, <system>, [INST]) to mimic platform control flags.
  • System Prompt Extraction: Direct interrogation tricks designed to reveal underlying proprietary instructions and internal schemas.
  • Smuggled Characters: Using non-printable zero-width characters (\u200B, \u200C, \uFEFF) to conceal malicious payloads from superficial keyword blocklists.
