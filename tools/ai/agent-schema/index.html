⚠️ Schema Validation & Autonomous Execution Disclaimer

A syntactically valid schema does not guarantee runtime security or prevent prompt injection. While strict JSON schemas prevent type-coercion bugs, hallucinated argument names, and structural formatting failures, they cannot prevent an LLM from passing malicious payloads inside valid string arguments (e.g., SQL injection inside a valid query string or command injection within a valid filename parameter).

Always enforce server-side argument validation, execution sandboxing, strict parameter whitelisting, and human-in-the-loop approvals before passing tool invocation arguments to backend APIs, OS shells, or database endpoints. Autonomous Tool Call Vulnerabilities

When autonomous AI agents invoke external functions via structured JSON calls, the schema serves as the operational contract between the non-deterministic language model and deterministic system execution code. Poorly specified schemas open critical attack surfaces:

  • Missing additionalProperties: false: Without this directive, models can hallucinate arbitrary argument keys that bypass downstream validation layers.
  • Unbounded String Parameters: Generic string types lacking enum constraints or regex pattern definitions allow attackers to smuggle prompt injections and shell commands into function parameters.
  • Vague Descriptions: Lack of precise parameter descriptions causes model confusion, triggering hallucinations and improper tool selection during multi-agent orchestration loops.

Zero Network Egress Guarantee

BitDark's Agent Tool Schema Validator audits and parses tool definitions locally in browser memory using native JavaScript JSON parsers and heuristic structural linters. No schemas, function names, descriptions, or parameters are ever communicated over the network.
