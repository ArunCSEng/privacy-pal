Understanding In-Memory AI Defense & Privacy

When evaluating sensitive system prompts, redacting proprietary API keys, or auditing training datasets, traditional online utilities require users to upload content to remote cloud servers. This exposes sensitive data to third-party logging, persistent indexing, and potential training ingestion.

Zero Network Egress

Every tool in this directory executes strictly within browser volatile RAM using HTML5 Canvas, Web Audio, and WebAssembly. Once this page finishes loading, disconnecting from the internet will not impact tool availability.

Dynamic Tool Discovery

When new defense utilities are deployed to /tools/ai/, this directory synchronizes via manifest.json automatically, registering newly published tools without manual interface rebuilds.

Ad Script Isolation

Third-party advertising scripts (including Google AdSense) are strictly confined to standard sandboxed layout elements and cannot read, access, or log your memory buffers or prompt strings.

Frequently Asked Questions

Are prompts or files ever transmitted to external AI servers?

No. All token counts, prompt checks, and manifest parses occur entirely in your local browser sandbox. No input data is sent to OpenAI, Anthropic, Google, or any remote server.

Can client-side prompt scanning guarantee 100% jailbreak protection?

No. Client-side heuristic scanners help identify known delimiters, role reversals, and hidden Unicode injections before deployment. However, production LLM systems require robust server-side guardrails and defense-in-depth architectures.

How does the automatic catalog synchronization work?

The client makes an asynchronous check to /tools/ai/manifest.json. When new tools are added to that JSON array, they are merged into your local view and cached in your browser's local storage automatically.
