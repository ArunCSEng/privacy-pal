DOM honeypots are detection heuristics, not complete access control solutions. While headless crawlers and naive spiders blindly parse every link in the DOM tree, sophisticated multi-modal scrapers running headless browser engines (Playwright, Puppeteer) evaluate bounding boxes, JavaScript visibility flags, and CSS computed layout styles before following links. How AI Honeypot Traps Operate

Modern Large Language Model web crawlers prioritize machine-readable context markers and extract anchor references indiscriminately across raw HTML documents. Honeypot generators exploit this behavioral disparity between human browsing and automated ingestion:

  • Visual Concealment: CSS properties like position: absolute; left: -9999px; or width: 0px; height: 0px; overflow: hidden; make the trap completely imperceptible to human users browsing with standard rendering engines.
  • Unconditional Spiders: Scraping bots running plain HTML parsing pipelines (e.g., BeautifulSoup, Scrapy, cURL, raw Cheerio scrapers) do not execute full layout rendering and follow all <a href="..."> anchors indiscriminately.
  • Telemetry & Blocking: When a request hits your designated honeypot route, your origin server or edge firewall can instantly tag the client IP address, update bad-reputation lists, or serve canary poison data.
