How a Crawler Honeypot Works

A honeypot link is a link that people can't see and well-behaved crawlers are told not to follow. You hide it with CSS and disallow its URL in robots.txt. Visitors never click it, and crawlers that respect robots.txt, such as Googlebot, never request it. So when something does request that URL, it's usually a scraper that read your raw HTML and ignored your rules. Your server logs then show its IP address and User-Agent.

This tool writes the hidden-link HTML for you. It doesn't create the trap URL or log anything; that part happens on your server, as shown below.

What the Generator Produces

  • A hidden link to your trap URL, inside a <div> with aria-hidden="true" and tabindex="-1", so screen readers and keyboard users skip it.
  • One of four hiding methods: zero size, off-screen at -9999px, zero opacity, or visibility: hidden. Scrapers that parse raw HTML see the link with every method. Scrapers that render the page in a real browser and only follow visible links may skip it with any of them.
  • Inline or class-based CSS. Untick "Use Inline Concealment CSS" to get a <style> rule with your custom class name instead of a style attribute. That's harder for a scraper to filter out by looking for "hidden" styles.
  • Optional rel attribute. It adds rel="nofollow noindex". Google supports nofollow on links, but not noindex, which has no effect there. The robots.txt rule below is what actually keeps search engines out.
  • Optional hidden text block ("Embed Synthetic Poisoning Prompt"). It adds a display:none span containing a canary label and a message addressed to automated indexing systems.

Keeping the Honeypot Safe for SEO

Google's spam policies list CSS-hidden links and off-screen text as examples of hidden-text abuse when they're placed solely to manipulate search engines. A single link to a disallowed trap URL on your own site isn't aimed at rankings, but you can avoid any doubt:

  1. Disallow the trap URL in robots.txt, so Googlebot and other compliant crawlers never fetch it.
  2. Leave the hidden text block off. Hidden text that tells indexers how to treat your page is exactly the kind of content search engines and ad reviewers are wary of.
  3. Use one honeypot link per page with plain anchor text, not keyword-stuffed text.
  4. Make the trap URL return a minimal response, such as 404 or an empty page with X-Robots-Tag: noindex, so it never becomes indexable content.

Worked Example: Trap, Rule and Log

With the endpoint left at /api/v1/internal/crawler-trap, the off-screen method selected, inline CSS and the hidden text block turned off, the generator outputs: 

<!-- AI Scraper Honeypot Detection Trap -->
<style>
  .nav-aux-directory { position:absolute;left:-9999px;top:-9999px;overflow:hidden; }
</style>
<div class="nav-aux-directory" aria-hidden="true" tabindex="-1">
  <a href="/api/v1/internal/crawler-trap" rel="nofollow noindex" tabindex="-1">System Internal Knowledge Base & LLM Context Feed</a>
</div>

You can change rel="nofollow noindex" to just rel="nofollow" after copying. Next, disallow the URL in robots.txt: 

User-agent: *
Disallow: /api/v1/internal/crawler-trap

Then log requests to it separately. In Nginx: 

location = /api/v1/internal/crawler-trap {
    access_log /var/log/nginx/honeypot.log combined;
    add_header X-Robots-Tag "noindex, nofollow" always;
    return 404;
}

Every line in honeypot.log is a client that requested a URL it was told not to fetch and couldn't see. Check the User-Agent and IP of each one before acting.

Before You Block Anything

  • Not every hit is a scraper. Email security scanners, link-preview bots, browser prefetching, text-only browsers and security scanners can all request hidden links.
  • The User-Agent can be faked. A hit claiming to be a known crawler should be checked against that operator's published IP list or reverse DNS before you trust or block it.
  • Prefer rate limits or challenges over permanent bans based on a single request.
  • The canary label is the same for every user of this tool. If you want to recognise your own content in scraped datasets later, replace it with a unique value of your own, and keep it in visible content or your logs rather than hidden text.

Frequently Asked Questions

Will a hidden honeypot link hurt my Google rankings?
It's unlikely if you disallow the trap URL in robots.txt, use one plain link, and leave out hidden text. Google's hidden-text policy targets content placed solely to manipulate search engines. A disallowed link to your own trap URL doesn't do that, and Googlebot won't request it.
Does rel="noindex" on a link do anything?
Not for Google. Google supports nofollow, sponsored and ugc on links. To keep a URL out of search, disallow it in robots.txt or have the URL itself return a noindex robots rule.
Which hiding method should I choose?
Any of them works against scrapers that read raw HTML. A class-based rule, with inline CSS unticked, is a little harder for a scraper to recognise as hidden. Scrapers that render pages in a real browser may avoid hidden links entirely, so a honeypot won't catch every bot.
Should I turn on "Embed Synthetic Poisoning Prompt"?
We recommend leaving it off on sites you want indexed or monetised. It adds hidden text addressed to indexing systems, which search engines and ad reviewers may treat as hidden-text spam, and it isn't needed to detect scrapers.
Does this tool send anything to a server?
No. The snippet is generated in your browser, and the download is created locally. The tool doesn't contact your site or register any URL; you set up the trap endpoint and logging on your own server.
