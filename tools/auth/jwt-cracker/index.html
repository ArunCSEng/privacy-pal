Vulnerability Profile: Weak HMAC-SHA256 (HS256) Secrets

HMAC-SHA256 is a symmetric signing algorithm where both the token issuer and consumer verify authenticity using the same shared secret key. Because the signature is calculated deterministically as HMAC-SHA256(header + "." + payload, secret), an attacker who intercepts a valid JWT can attempt an offline dictionary or brute-force attack entirely without interacting with the authentication server.

  • Entropy Requirements: RFC 7518 specifies that HS256 keys must be at least 256 bits (32 bytes) of cryptographically random entropy.
  • Common Weaknesses: Developers often sign staging or production tokens with simple dictionary words (e.g., secret, password, jwt-secret, or company domain names), which can be recovered in seconds.
  • Blast Radius: Once an attacker cracks the secret key, they can forge arbitrary tokens with altered claims (such as elevating privileges to admin: true) that the backend will trust as authentic.
