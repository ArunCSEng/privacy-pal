A clean scan is not a guarantee. This checks a fixed set of patterns plus an entropy heuristic, so it can miss unknown or obfuscated secrets and may flag harmless high-entropy strings. What This Scanner Looks For

Hardcoded secrets in code and config are a leading cause of breaches: an API key or private key committed to a repository or pasted into a public snippet can be found and abused within minutes. This tool scans text you paste for two things: known secret formats, and high-entropy strings that look random enough to be secrets.

How the Entropy Check Works

With "Shannon Entropy Analysis" ticked, the scanner also measures the randomness of long tokens that didn't match a known pattern. It flags a token when its entropy per character crosses a threshold: about 3.4 bits for hex-looking strings and about 4.45 bits for mixed Base64-style strings. That catches random-looking secrets from providers the pattern list doesn't know. In testing, a random 40-character hex string flagged at 3.97 bits and a Base64-style one at 5.13 bits, while ordinary words and a UUID did not.

How to Use the Secret Scanner

  1. Paste the code, .env file or config you want to check, and click "Scan for Secrets".
  2. Keep "Mask Detected Secrets" on so findings are partly hidden in the results.
  3. Review each finding. Severity reflects the pattern, not your context: a test key or an example value will still be flagged.
  4. Act on real hits by removing the secret from the code and rotating it (see below).

What a Pattern Scanner Can't Catch

  • Formats it doesn't know. New or niche providers, and custom internal tokens, may not match any pattern. Turn on entropy analysis to catch the random-looking ones, but a short or structured secret can still slip through.
  • Split or obfuscated secrets. A key assembled from several variables, Base64-wrapped, or built at runtime won't match.
  • Only what you paste. It scans the text in the box, not your whole repository or its history. For that, run a dedicated scanner such as gitleaks or TruffleHog, ideally as a pre-commit hook and in CI.
  • Context. It can't tell a live production key from a dummy, so expect some findings on examples and tests.

If You Find a Real Secret: Rotate It

Deleting a secret from your code is not enough if it was ever committed or shared. Treat any exposed secret as compromised:

  1. Revoke and reissue the key at the provider, so the old value stops working.
  2. Assume it leaked. If it was pushed to a repository, it's in the git history and possibly in forks, clones, logs and caches, even after you delete the line.
  3. Move secrets out of code into environment variables or a secret manager, and add patterns like .env to .gitignore.
  4. Check for misuse in the provider's audit logs around the exposure window.

Frequently Asked Questions

Is it safe to paste my code and secrets here?
The scanning runs entirely in your browser and the tool makes no network requests with what you paste, so nothing is uploaded. Still, treat any secret that has already been exposed as compromised and rotate it, regardless of where you scanned it.
A clean scan means my code has no secrets, right?
Not necessarily. The scanner knows a fixed set of patterns plus an entropy check, so it can miss unknown formats, split or obfuscated secrets, and anything outside the text you pasted. Use it as one check, alongside a repository scanner in CI.
Why was a harmless string flagged as high entropy?
The entropy check flags long random-looking tokens, which occasionally includes hashes, IDs or encoded data that aren't secrets. Review each finding in context; if it isn't sensitive, you can ignore it. You can also turn entropy analysis off to see only known patterns.
I removed the secret from my latest commit. Am I safe?
No. If it was ever pushed, it remains in the git history and may have been cloned or logged. Rotate the secret at the provider so the exposed value no longer works, then clean the history if needed.
Does it detect every provider's keys?
No. It covers common ones such as AWS, GitHub, Stripe, Google, Slack, private keys, database URIs and JWTs, plus generic secret assignments. Other providers may only be caught by the entropy check, or not at all.
