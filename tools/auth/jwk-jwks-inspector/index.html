JWK, JWKS and PEM in Brief

  • JWK (JSON Web Key, RFC 7517) is a public or private key written as JSON. An RSA public key has kty, n (modulus) and e (exponent); an elliptic-curve key has kty, crv, x and y. Optional fields include kid (key ID), use and alg.
  • JWKS is a set of keys: {"keys": [...]}. OpenID Connect providers publish one at the jwks_uri listed in their discovery document, often /.well-known/jwks.json, so apps can verify the signatures on ID tokens and access tokens.
  • PEM is the Base64 text format most server libraries and OpenSSL expect. BEGIN PUBLIC KEY is SubjectPublicKeyInfo (SPKI), which works for RSA and EC; BEGIN RSA PUBLIC KEY is the older RSA-only PKCS#1 format.

How to Use the JWK Inspector

  1. Paste a JWK or JWKS, for example the contents of an identity provider's jwks_uri, and click "Inspect & Convert to PEM".
  2. Match keys by kid. A JWT's header contains a kid; the matching key in the set is the one that verifies it.
  3. Copy or download the PEM for libraries that need it, such as OpenSSL, nginx or older JWT libraries.
  4. For the reverse, switch to "PEM → JWK", paste a public key and copy the JWKS.

Worked Example: The RFC 7638 Thumbprint

RFC 7638 defines a JWK thumbprint: a stable SHA-256 fingerprint of the key's required fields. Its example RSA key (from section 3.1, with kid "2011-04-29") gives the thumbprint below. Paste that key into this tool and you get exactly the same value: 

NzbLsXh8uDCcd-6MNwXF4W_7noWXFZAfHkxZsRGC9Xs

The calculation keeps only the required members, sorts them alphabetically, and writes them as compact JSON with no spaces: 

{"e":"AQAB","kty":"RSA","n":"0vx7agoebGcQSuuPiLJXZptN9nndrQmb…"}

That string is hashed with SHA-256 and Base64url-encoded. For EC keys the members are crv, kty, x and y. Optional fields such as kid, use and alg don't change the thumbprint, so it's a reliable way to identify a key.

We also checked the PEM output against Node.js's built-in crypto library for RSA-2048, RSA-4096, P-384 and P-521 keys, and every PEM matched byte for byte.

Practical Notes

  • Private keys: if a JWK includes private fields (d, p, q and so on), the tool still accepts it and outputs only the public PEM, without a warning. Avoid pasting private keys into any web page; strip them first.
  • Key rotation: providers publish old and new keys side by side in the JWKS during rotation. Cache the set, but refetch it when a token arrives with an unknown kid.
  • Thumbprints in other standards: DPoP (RFC 9449) binds tokens to a client key using its JWK thumbprint (jkt), and many systems use the thumbprint as the kid.

Frequently Asked Questions

How do I convert a JWKS from my identity provider to PEM?
Open the provider's jwks_uri, usually listed in /.well-known/openid-configuration, copy the JSON, paste it into the JWK/JWKS → PEM tab and click Inspect & Convert. You get one PEM per key, labelled with its kid.
What is a JWK thumbprint?
It's the SHA-256 hash of a key's required members in sorted, compact JSON, Base64url-encoded (RFC 7638). It identifies a key regardless of optional fields. This tool's output matches the RFC 7638 example: NzbLsXh8uDCcd-6MNwXF4W_7noWXFZAfHkxZsRGC9Xs.
What's the difference between BEGIN PUBLIC KEY and BEGIN RSA PUBLIC KEY?
BEGIN PUBLIC KEY is SubjectPublicKeyInfo (SPKI), which includes an algorithm identifier and works for RSA and EC keys. BEGIN RSA PUBLIC KEY is PKCS#1, which holds only an RSA modulus and exponent. This tool outputs SPKI and reads both.
Does it support Ed25519 keys?
No. It handles RSA and EC keys on P-256, P-384 and P-521. Ed25519 keys use kty "OKP" (RFC 8037) and return an "unsupported key type" error.
Is my key uploaded?
No. Parsing, conversion and hashing run in your browser using JavaScript and Web Crypto, and the tool makes no network requests with your key. Public keys are safe to share, but strip private fields before pasting anything.
