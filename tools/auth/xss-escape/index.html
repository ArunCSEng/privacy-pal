Contextual XSS Sanitizer & Encoder

Evaluate and transform potentially malicious strings into safe representations across HTML Body, Attribute, JavaScript, URI, and CSS execution contexts.

Load Attack Payload:
1. HTML Body Context <div>...</div> 
-
Escapes &, <, >, ", ', and / into HTML entity references.
2. HTML Attribute Context <input value="..."> 
-
Alphanumeric strict hex-entity escaping (&#xHH;) preventing delimiter quote breakouts and unquoted attribute injections.
3. JavaScript String Literal Context <script>let v = '...';</script> 
-
Unicode escapes non-alphanumerics (\uXXXX) and strips closing HTML script tags to prevent immediate script termination.
4. URI Component Context <a href="https://site.com?q=..."> 
-
RFC 3986 percent-encoded format. Does not guarantee safety if used as a raw scheme (e.g., javascript: links).
5. CSS Value Context <style>body { color: ...; }</style> 
-
Hexadecimal CSS escapes (\HH ) preventing style block breakouts and CSS expression execution.

Contextual escaping is a defense-in-depth practice that must be implemented according to strict syntactic boundaries. Encoding dynamic content for one context (such as HTML entity encoding) will not protect an application if placed inside an incompatible context (such as raw JavaScript blocks, event handlers, or href URI targets). Always combine contextual output escaping with contextual HTML sanitization and robust Content Security Policies (CSP).

Why Contextual Encoding Matters

Cross-Site Scripting (XSS) occurs when untrusted user input is injected into an application without proper contextual translation. Web browsers parse documents through distinct tokenizer phases: the HTML parser, the JavaScript engine, the CSS interpreter, and the URI resolver. What is safe inside an HTML paragraph element may result in immediate script execution inside an attribute or JavaScript block.

  • HTML Entity Encoding: Translates characters like < and > into &lt; and &gt;. While sufficient for inner text, it fails inside direct JavaScript script tags because the JS parser does not decode HTML entities.
  • Attribute Escaping: Must account for single-quoted, double-quoted, and unquoted attributes. Hexadecimal entity encoding ensures that space characters and quotes cannot terminate the attribute container.
  • JavaScript Literal Escaping: Requires backslash or Unicode representation (\u0027, \u0022) as well as protection against </script> tags, which the HTML parser prioritizes above JavaScript evaluation.
