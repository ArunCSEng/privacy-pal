What SAML Is

SAML (Security Assertion Markup Language) 2.0 is the XML standard behind much enterprise single sign-on. When you log in to a company app through an identity provider (IdP) such as Okta, Microsoft Entra ID or Ping, the IdP sends the app a signed XML assertion that says who you are and which attributes you have. The app (the service provider, SP) trusts it because of the IdP's digital signature.

The messages travel Base64-encoded, and the SAMLRequest on the redirect binding is also DEFLATE-compressed, so they're unreadable until decoded. This tool decodes all of that and lays out the fields.

It accepts raw XML, Base64, URL-encoded SAMLResponse=/SAMLRequest= values, and DEFLATE-compressed redirect-binding requests, and it handles Response, Assertion and AuthnRequest messages.

Important: It Decodes, It Doesn't Verify

The "XML Digital Signature" field tells you only whether a <ds:Signature> element exists and names its algorithm. It does not check the signature against a certificate. We tested this: a token with the signature value replaced by TOTALLYBOGUS== still reports "Signed (rsa-sha256)" and a "Valid Envelope" banner, as long as its dates are current.

So never decide a token is trustworthy from this tool's output. Forging or tampering with SAML responses is a real attack class, including signature-stripping and XML signature-wrapping. Only a proper SAML library, validating the signature against the IdP's known certificate, can tell you a token is authentic. Use this tool to read and debug tokens, not to authenticate them.

How to Use the SAML Decoder

  1. Paste a token from your browser's developer tools (the SAMLResponse form field during login) or a SAMLRequest from a redirect URL, and click "Decode Token". You can also drop an .xml file.
  2. Check the Subject, Issuer and Validity against what you expect.
  3. Read the attributes to debug missing roles or wrong claim names, the most common SSO problems.
  4. Treat "Signed" as "a signature is present", then verify it properly in your SP or with a SAML library.

Common SAML Problems to Debug

  • Clock skew. If the SP's clock differs from the IdP's, a valid assertion can look expired or not-yet-valid. Allow a small tolerance.
  • Audience mismatch. The AudienceRestriction must name your SP's entity ID, or the SP rejects the assertion.
  • Wrong attribute names. Apps expect specific claim names (for example an email or a roles attribute); a mismatch shows up here as attributes with unexpected names.
  • NameID format. The SP and IdP must agree on the format (email address, persistent, transient).
  • Unsigned assertions. If this tool shows "Unsigned", the SP should reject the token; production assertions should be signed.

SAML tokens carry personal data and are effectively login credentials while valid. Decode them in a trusted local tool like this one, not a public server, and avoid sharing real tokens.

Frequently Asked Questions

Does this tool verify the SAML signature?
No. It reports whether a ds:Signature element is present and its algorithm, but it doesn't check the signature against a certificate. A forged token with an invalid signature still shows as "Signed". Verify signatures in your service provider or with a SAML library.
What's the difference between a SAMLRequest and a SAMLResponse?
The SP sends a SAMLRequest (an AuthnRequest) to start login; the IdP returns a SAMLResponse containing the signed assertion about the user. On the redirect binding the request is DEFLATE-compressed and Base64-encoded, which this tool decompresses automatically.
Why does my assertion show as expired?
The current time is past the Conditions NotOnOrAfter value. This is often clock skew between the IdP and SP rather than a real expiry. Synchronise clocks with NTP and allow a small tolerance on the SP.
Is SAML still used, or has OIDC replaced it?
Both are in wide use. OpenID Connect is common for new consumer and mobile apps, while SAML 2.0 remains standard for enterprise SSO and many existing business applications, so you'll still meet SAML tokens regularly.
Is my token uploaded?
No. Decoding, decompression and parsing run in your browser, and the tool makes no network requests with your token. Because a valid SAML token is a live credential, still avoid pasting real production tokens anywhere you don't control.
