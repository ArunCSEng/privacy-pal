Deconstructing SSL/TLS Cipher Suites

A cipher suite defines the exact combination of cryptographic algorithms an endpoint will use to negotiate keys, authenticate peers, and protect network sessions.

  • Key Exchange: Dictates how symmetric session keys are established. Modern suites strictly mandate Ephemeral Diffie-Hellman (ECDHE or DHE) to ensure Perfect Forward Secrecy (PFS). Static RSA key exchanges are broken because compromising the server's private key retroactively decrypts all past recorded traffic.
  • Authentication: Verifies server authenticity via certificates signed using RSA, ECDSA, or Ed25519.
  • Symmetric Bulk Encryption: Encrypts payload traffic. AEAD (Authenticated Encryption with Associated Data) ciphers like AES-GCM and ChaCha20-Poly1305 provide simultaneous encryption and integrity verification, avoiding the padding oracle flaws of CBC mode (such as POODLE and Lucky Thirteen).
  • TLS 1.3 Architectural Redesign: In TLS 1.3, the cipher naming syntax is radically simplified (e.g., TLS_AES_256_GCM_SHA384). Key exchange and authentication mechanisms are separated into independent negotiation extensions.
