Understanding Subresource Integrity (SRI)

Subresource Integrity is a security feature standard defined by the W3C that allows web browsers to verify that resources fetched from third-party CDNs or external servers have not been manipulated, corrupted, or maliciously injected with unauthorized modifications.

  • Verification Mechanism: The browser calculates the cryptographic digest of the received file payload and compares it against the base64-encoded digest provided within the integrity attribute.
  • Execution Blocking: If the calculated digest does not match the attribute exactly, the browser discards the payload and refuses to execute scripts or apply stylesheets.
  • Mandatory CORS Header: When loading cross-origin assets with SRI, the asset must be served with appropriate CORS headers (Access-Control-Allow-Origin) and requested with crossorigin="anonymous".

Choosing Between SHA-256, SHA-384, and SHA-512

While the SRI specification permits SHA-256, SHA-384, and SHA-512, the W3C working group strongly recommends SHA-384 as the optimal balance between collision resistance, resistance against length-extension attacks, and performance overhead on low-power devices.
