What Subresource Integrity Does

When you load a script or stylesheet from a CDN, your page runs whatever that server sends. If the CDN is compromised or the file is tampered with in transit, the malicious version runs on your site. Subresource Integrity (SRI) prevents that: you add an integrity attribute containing a cryptographic hash of the exact file you expect, and the browser refuses to run the resource if what it downloads doesn't match. 

<script src="https://cdn.example.com/app.js"
        integrity="sha384-<hash>"
        crossorigin="anonymous"></script>

This tool generates that hash, in SHA-256, SHA-384 and SHA-512, from text you paste, a local file, or a fetched URL, and builds the ready-to-use tag. SHA-384 is the value the W3C recommends.

Worked Example You Can Verify

Paste this exact content (the text console.log('hello'); followed by a newline) into the Raw Text tab, and the tool produces: 

sha256-Xjmz//kjTHsbOoy1yvNczqpm5xq9IQ7fsNW79Rzzh00=
sha384-eEqgsNuDqSzbarn2kIY7c4WH6zkoJrjJRQIhlYgVwRR+6Eb8tkfTItTNLlIjbE3O

You can reproduce the SHA-384 value on the command line, which is how to confirm any SRI hash: 

printf "console.log('hello');\n" | openssl dgst -sha384 -binary | openssl base64 -A

It prints eEqgsNuDqSzbarn2kIY7c4WH6zkoJrjJRQIhlYgVwRR+6Eb8tkfTItTNLlIjbE3O, matching the tool. Note the SHA-384 value is always 64 Base64 characters with no trailing =; a different length means a different algorithm or a malformed hash.

How to Use the SRI Generator

  1. Choose an input. Paste code, upload the file, or enter a URL. The URL must send CORS headers (Access-Control-Allow-Origin) for your browser to fetch it.
  2. Pick the resource type (<script> or <link>) so the generated tag is correct.
  3. Copy the SHA-384 tag into your HTML, keeping the src/href and adding crossorigin="anonymous".
  4. Hash the exact file you'll serve. Minification, a trailing newline or a version bump all change the hash.

Things to Get Right

  • Add crossorigin="anonymous" for cross-origin resources. Without it the browser won't enforce SRI on a CDN file, and the resource may be blocked or silently skipped.
  • Only pin files that don't change. SRI suits versioned, immutable URLs (for example a pinned @1.2.3 path). If the file updates, the hash breaks and the resource stops loading, so don't use it on assets that change at the same URL.
  • A mismatch blocks the resource. That's the point, but it means a legitimate update without a matching hash takes your script or stylesheet offline. Update both together.
  • You can list multiple hashes separated by spaces (for example during a rollover); the browser accepts the resource if any one matches.
  • SRI protects integrity, not availability or privacy. It doesn't stop a CDN going down, and it isn't a substitute for HTTPS or a Content-Security-Policy.

Where SRI Fits

SRI pairs well with a Content-Security-Policy: CSP controls which origins can load scripts, and SRI verifies that a specific file from an allowed origin is the exact one you trust. For resources you host yourself and deploy together, SRI adds less, since you already control the file; it's most valuable for third-party CDN assets.

Frequently Asked Questions

Which hash algorithm should I use?
SHA-384 is the W3C-recommended default and what this tool highlights. SHA-256 and SHA-512 are also valid SRI algorithms. All three are supported by browsers; pick one and use its full value, including the prefix.
Why did my resource stop loading after I added integrity?
The downloaded file no longer matches the hash. Common causes are the file being updated, served minified differently, or missing crossorigin="anonymous" on a cross-origin resource. Regenerate the hash from the exact file you serve and add the crossorigin attribute.
Can I use SRI on a "latest" CDN URL?
No. A URL that serves a changing file (like a "latest" alias) will break the hash whenever it updates. Pin a specific immutable version URL and generate the hash for that exact file.
Does SRI replace HTTPS or CSP?
No. SRI verifies a file's contents; HTTPS protects the connection and CSP controls which sources are allowed. Use them together. SRI is specifically about catching a tampered or swapped third-party file.
Is my file or code uploaded?
Not for the text and file modes: hashing runs in your browser with the Web Crypto API. The URL mode does fetch the asset you enter from your browser to read its bytes, but it isn't sent to this site. Nothing you paste or upload is uploaded anywhere.
