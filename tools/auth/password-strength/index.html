⚠️ Limitations & Disclaimer

This estimate is a best case, not a guarantee. It measures length and character types, so it overrates predictable passwords, repeats and passphrases, and the cracking times assume pure brute force. How This Meter Estimates Strength

The tool counts which character types you use (lowercase, uppercase, digits, symbols) to get a "pool" size, then estimates entropy as length × log2(pool). It subtracts a few points for short length, single character types, long repeats and a handful of keyboard sequences. More entropy bits means more guesses to try.

This formula is accurate for truly random strings, like the ones the "Generate" button makes. It is not accurate for passwords a person chose, because it assumes every character is independent and unpredictable. Real passwords rarely are, so treat the bits here as a best case, not a guarantee.

Real attackers don't brute-force character by character; they try words, dates, keyboard patterns and known leaked passwords first. Tools like zxcvbn, which model those patterns, give far lower and more realistic scores for human-chosen passwords.

Passphrases: Why Words Beat Characters

The strength of a random-word passphrase comes from how many words could have been chosen, not how many letters it has. The famous correct horse battery staple example comes from XKCD 936, which picks four common words from a pool of roughly 2,000. That's about 11 bits per word, or 44 bits total, regardless of the 28 characters. This tool counts those characters and reports 165 bits, which is far too high.

Diceware is the same idea with a bigger list. The standard Diceware and EFF wordlists hold 7,776 words, about 12.9 bits each, so a six-word Diceware passphrase is roughly 77 bits. The lesson: choose the words randomly from a known list, and use enough of them. Adding more random words raises strength much faster than adding symbols to a single word.

Reading the Cracking Times

The time estimates assume an attacker guesses randomly across the whole keyspace, at a fixed rate, and finds the password halfway through. That's the right model for a random string against a given hash speed, and the rows reflect how much the hash matters: a slow, salted hash like Argon2 or bcrypt (10,000 guesses/sec here) buys enormous time compared with a fast hash like MD5 (billions/sec). But for a human-chosen password the times are too optimistic, because the attacker reaches it long before exhausting the space. Use the times to compare hash choices and password lengths, not as a promise.

Practical Advice

  • Length first. A longer random passphrase beats a short complex one. Modern guidance (NIST SP 800-63B) favours length and discourages forced complexity rules.
  • Use a password manager. Let it generate and store long random passwords, so you only remember one strong master passphrase.
  • One password per site. Reuse is the biggest real-world risk: a leak on one site becomes a key to others.
  • Check against breaches. Even a high-entropy password is useless if it has already leaked. Services like Have I Been Pwned let you check safely.
  • Turn on two-factor authentication wherever you can; it protects you even if a password is stolen.

Frequently Asked Questions

Why does this tool rate a repeated string as strong?
Because it estimates strength from length and character types, and only lightly penalises repeats. Forty identical letters score high here but would be guessed instantly in reality. Treat the score as a ceiling, and rely on randomness, not raw length, for real strength.
Is a passphrase like "correct horse battery staple" strong?
Only if the words are chosen randomly, and it's the number of words and the size of the list that matter, not the letters. The XKCD example is about 44 bits. A random six-word Diceware passphrase is around 77 bits. This tool overstates passphrases because it counts characters.
How many bits of entropy is "enough"?
For a password behind a slow, salted hash with rate limiting, the low tens of bits can be adequate; for something that may be cracked offline against a fast hash, aim higher, roughly 80 bits or more. Because this tool overestimates human passwords, build in a margin.
Should I add symbols or make it longer?
Longer wins. Adding a symbol to a word adds little if the word is predictable. Adding another random word, or more random characters, increases the number of possibilities far more. Length plus randomness beats complexity tricks.
Is my password sent anywhere?
No. All analysis runs in your browser, and the tool makes no network requests with what you type. Still, as a habit, don't paste a password you actively use into any website; test a sample of the same style instead.
