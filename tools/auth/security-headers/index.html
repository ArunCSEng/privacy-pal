⚠️ Limitations & Disclaimer

A passing rating isn't a full security review. The tool checks that CSP exists, not whether it's strong, and reports information-leak headers as low without lowering the grade. Headers are one layer of defence. Verify your live headers after deploying, since a CDN or proxy can change them. Results are provided as-is; BitDark.net is not liable for decisions made using them.

What Security Headers Do

HTTP response headers let a server tell the browser how to behave: force HTTPS, block framing, stop MIME sniffing, limit what the referrer reveals, and more. They're a cheap, high-value layer of defence, and most are a one-line change in your web server or app. This tool checks a set of headers you paste and rates how well they're configured. It analyses text only; it doesn't fetch your site.

What This Analyzer Checks

HeaderProtects againstHow it's graded
Strict-Transport-Security (HSTS)SSL stripping, HTTP downgradeHigh if missing; medium if max-age is under ~120 days or includeSubDomains is absent
Content-Security-PolicyXSS, injectionHigh if missing; pass if present (presence only)

Referrer-PolicyURL/token leakageMedium if missing or weak (unsafe-url)
Permissions-PolicyUnwanted camera/mic/geolocationLow if missing
Server, X-Powered-By, X-AspNet-VersionVersion fingerprintingLow if present (information leak)

The overall rating is driven by the worst finding: any high issue makes it "Poor / High Risk", any medium makes it "Moderate Hardening", and otherwise it's "Strong / Compliant". Low-severity items, such as an exposed Server header or a missing Permissions-Policy, are reported but don't lower the top rating, so "Strong" still leaves a little room to tighten.

How to Use the Analyzer

  1. Get your headers. Run curl -I https://yoursite.com, or copy the response headers from your browser's Network tab.
  2. Paste them and click "Analyze Headers", or load a sample to compare.
  3. Fix high findings first, then medium, then the low information-leak items.
  4. Re-check after deploying, since a proxy or CDN can add or strip headers.

A Solid Baseline

Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
Content-Security-Policy: default-src 'self'; object-src 'none'; frame-ancestors 'self'; base-uri 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), camera=(), microphone=()
  • Only add preload once you're sure every subdomain works over HTTPS; preload is hard to undo.
  • CSP presence isn't CSP quality. This tool only checks that CSP exists. A policy with 'unsafe-inline' or wildcards can still be weak, so evaluate the policy itself separately.
  • You don't need X-XSS-Protection. It's deprecated and best set to 0 or omitted; modern defence comes from CSP. This tool correctly doesn't ask for it.
  • frame-ancestors supersedes X-Frame-Options, but keeping X-Frame-Options helps older browsers; the tool accepts either.

Frequently Asked Questions

Does a "Strong / Compliant" rating mean my site is fully secure?
No. It means no high or medium header issues were found. The tool still reports low items like information-leak headers without lowering the grade, it only checks that CSP exists rather than whether it's strong, and headers are just one layer. Keep hardening beyond a passing rating.
Does this tool check my live website?
No. It analyses the header text you paste, entirely in your browser, and makes no network request to your site. Fetch your headers with curl or the Network tab and paste them in.
What's the most important header to add first?
If you're on HTTPS, HSTS and a Content-Security-Policy give the most protection, against downgrade attacks and XSS respectively. X-Content-Type-Options: nosniff is a trivial, high-value addition too.
Why does it flag my Server header?
Headers like Server and X-Powered-By reveal your software and version, which helps an attacker target known vulnerabilities. It's a low-severity finding: remove or generalise them where you can, but it won't make or break your rating.
Is the HSTS max-age threshold here the recommended value?
The tool warns only when max-age is under about 120 days, but the recommended production value is at least one year (31536000 seconds). Use the longer value, and includeSubDomains, for full protection even though a shorter one may still pass.
