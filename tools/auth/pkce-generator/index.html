How PKCE Mitigates Authorization Code Interception

The Proof Key for Code Exchange protocol (standardized in RFC 7636) prevents authorization code interception attacks against public clients (such as Single Page Applications and mobile applications) that cannot securely store a traditional client secret.

  • Code Verifier: A cryptographically random string using the unreserved URI character set [A-Z], [a-z], [0-9], -, ., _, and ~, with a minimum length of 43 characters and a maximum length of 128 characters.
  • Code Challenge (S256): Created by hashing the code verifier with SHA-256 and encoding the result in Base64URL without padding: BASE64URL(SHA256(ASCII(code_verifier))).
  • Verification Step: The authorization server holds the challenge during the authorization phase and evaluates it against the raw verifier submitted during the token exchange phase before issuing tokens.

Deprecated Plain Mode

While RFC 7636 defines the plain transformation (where code_challenge = code_verifier), it is only supported for legacy endpoints unable to compute SHA-256. Modern OAuth 2.1 specifications explicitly require the S256 transformation method.

Zero Network Egress Security Guarantee

Generating authentication credentials over remote web APIs creates an unnecessary point of eavesdropping. BitDark generates all randomness and cryptographic SHA-256 digests entirely within your local browser sandbox via window.crypto.getRandomValues and window.crypto.subtle.digest. Zero bytes are transferred over the wire.
