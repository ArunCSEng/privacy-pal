⚠️ Limitations & Disclaimer

This simulates browser behaviour; it does not observe your traffic. The audit applies the referrer policy rules to the two URLs you enter and reports what a browser would send. It is not a measurement of what your browser did on some other site, and real behaviour can differ where a site sets a per-element policy, where an extension interferes, or where a browser applies additional restrictions of its own. The live navigation test is the exception: it makes a real request so you can compare the simulation against reality. One caveat worth repeating \u2014 a referrer policy governs one header and nothing else. A script on the page can still send the full URL anywhere it likes. Results are provided as-is; BitDark.net is not liable for decisions made from them.

What This Tool Does

Enter the page a user is on and the destination a request goes to, choose a policy, and the audit shows the exact value the Referer header would carry. Running the same URL pair through each of the eight policies in turn is the fastest way to understand a mechanism that is otherwise easy to get wrong.

The default source URL in the placeholder is deliberately chosen: a password-reset path with a token in the query string. That is the case where the difference between policies stops being academic.

How to Use the Tool

  1. Enter a source URL representing the page the user is on. Use a realistic one from your own application, including whatever appears in its path and query string.
  2. Enter a destination URL — a third-party script, an analytics endpoint, an image host, or an outbound link.
  3. Select a policy under Referrer Policy Under Audit and click Audit Policy Behavior.
  4. Read what would be sent, then repeat for each policy in the list. The contrast between unsafe-url and no-referrer on the same pair makes the stakes obvious.
  5. Change the destination scheme to HTTP and re-run the strict policies. Watch the referrer vanish — that downgrade rule is the part most people do not know about.
  6. Use Test Live Navigation Referrer to see a real request rather than a simulation, and confirm your browser behaves as the model predicts.

What Each Policy Sends

no-referrer sends nothing, ever. same-origin sends the full URL to your own origin and nothing to anyone else. origin sends only the scheme, host and port everywhere, including to your own pages. strict-origin does the same but sends nothing on an HTTPS-to-HTTP downgrade.

origin-when-cross-origin sends the full URL internally and the origin externally. strict-origin-when-cross-origin — the modern browser default — does the same and additionally drops the referrer on a downgrade. no-referrer-when-downgrade is the old default: full URL everywhere except on a downgrade, which is far more leakage than most sites intend. unsafe-url sends the full URL unconditionally.

How URLs Leak Secrets

The failure mode is specific and has caused real incidents. A site puts something sensitive in a URL — a password-reset token, a session identifier, a shared document key, a search query, a record ID. A user opens that page. The page loads an analytics script, a font, an advertisement, an embedded widget. Under a permissive policy, each of those third parties receives the full URL in the Referer header, token included.

The browser default now prevents the worst of this, which is why it changed. But defaults only help where nothing overrides them, and the structural fix is not to put secrets in URLs at all: single-use tokens that are consumed immediately, identifiers in the request body rather than the query string, and a restrictive policy as a backstop rather than the only defence.

A Worked Example You Can Reproduce

Use the placeholder values: a reset URL carrying a token and a user parameter, and a third-party CDN script as the destination. Under unsafe-url, the token and the username both arrive at the CDN. Under the default strict-origin-when-cross-origin, only the origin is sent — the CDN learns which site, not which page or which token. Under no-referrer, nothing. Now switch the destination to plain HTTP and re-run the default policy: the referrer disappears entirely, because sending any referrer across a downgrade exposes it to anyone on the path. Three runs, three very different disclosures, from the same page.

Frequently Asked Questions

Why is the header spelled Referer?
A misspelling in the original HTTP specification that was never corrected, because fixing it would have broken every implementation. The header is Referer with one r; the JavaScript property and the policy directive use the correct referrer. Both spellings are right in their own context, which trips up almost everyone at least once.
What is wrong with unsafe-url?
It sends the full URL — path and query string included — to every destination, including over plain HTTP. If any page on your site carries a token, a session identifier, a search term or a record ID in its URL, that value goes to every third party whose resources the page loads. The name is a warning, and it is accurate.
What does the browser default actually do?
Strict-origin-when-cross-origin sends the full URL for same-origin requests, only the origin for cross-origin requests, and nothing at all when going from HTTPS to HTTP. It is a sensible compromise: your own pages keep the detail they need for analytics, third parties learn which site sent the request but not which page, and downgraded connections leak nothing.
Does a referrer policy protect against everything?
No. It controls one header. A page can still pass the current URL to a third party through a script, a query parameter it constructs, or a beacon, and none of that is governed by the referrer policy. The policy is a default for the browser, not an enforcement mechanism against code running on the page.
Is anything sent to a server by this audit?
The simulation is pure computation in your browser — it applies the policy rules to the URLs you type and shows the result. The optional live navigation test does make a real request, which is the point of it; the simulation on its own transmits nothing.
