⚠️ Steganographic Security & Operational Disclaimer

LSB steganography is fragile and does not constitute end-to-end cryptographic protection on its own. Lossy compression routines (such as JPEG re-encoding, WebP re-sampling, screenshotting, or messaging platforms like Discord, WhatsApp, and Slack) discard least-significant bit data, irreversibly corrupting embedded payloads. Furthermore, standard statistical steganalysis techniques (Chi-square analysis, RS analysis) can identify anomalies in raw color channels. Always pre-encrypt sensitive payloads with authenticated encryption (e.g., AES-GCM) prior to embedding. How Canvas LSB Steganography Operates

Least Significant Bit (LSB) steganography embeds covert message bits into the least perceptible bits of RGB color channels in digital graphics:

  • Color Channel Bit Modification: Standard 24-bit RGB images dedicate 8 bits (0–255) to Red, Green, and Blue channels per pixel. Flipping the lowest bit alters color luminescence by less than 1%, which is imperceptible to the naked eye.
  • Delimiter & Framing: To allow deterministic recovery without hardcoding payload length, a 32-bit signature delimiter is encoded into the bitstream to mark the exact termination of the payload data.
  • Format Constraints: Lossless PNG or WebP must be utilized for transmission. Lossy JPEG quantizations discard higher-frequency color information and destroy LSB modifications.

Zero Network Egress Architecture

All pixel buffer operations, canvas rasterizations, and bitwise stream transformations are calculated in memory via the HTML5 CanvasRenderingContext2D and ImageData APIs. No imagery or hidden text is sent to an external server or logged remotely.
