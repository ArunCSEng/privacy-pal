⚠️ Limitations & Disclaimer

Removing metadata is not redaction, and it is not a guarantee of anonymity. This tool targets the document information dictionary and XMP packets. It does not alter page content, embedded images and their own metadata, attachments, annotations, form field values, or earlier revisions left behind by incremental updates — any of which can identify the author or reveal text someone thought was gone. If a document contains something that must not be disclosed, the only safe approach is software built for redaction, which removes the underlying content rather than covering it, followed by verification on the output. A black rectangle drawn over text leaves the text fully extractable. Everything runs in your browser and nothing is uploaded. What This Tool Does

Load a PDF and the tool reports the metadata it carries: the document information dictionary, with fields such as author, title, subject, keywords, creator, producer and creation and modification timestamps; and any XMP packets, which hold a richer XML description written by editing software. Then it produces a copy with those removed.

The reporting step is the one people skip and the one worth doing. Most PDFs leaving an organisation name the person who made them, the software that wrote them, and when — details the sender never consciously added.

How to Use the Tool

  1. Load the PDF by dropping it on the page or selecting it.
  2. Read the metadata report first. Check the author and creator fields for a real name, the producer field for software and version, and the timestamps for anything revealing about when the document was prepared.
  3. Note whether XMP is present. Files that have passed through professional editing tools often carry XMP alongside the info dictionary, and it can contain substantially more.
  4. Click Download Sanitized PDF to get the cleaned copy.
  5. Verify by re-loading the output into this tool. The report should come back empty — a check you can run yourself rather than taking on trust.
  6. Open the sanitised copy and read it. Metadata removal does nothing about a name in a footer, a signature block, a letterhead or a tracked comment, and those are what actually identify most documents.

Where Identifying Data Hides in a PDF

PDF is a container with many places to put things, and over the years software has used most of them. Beyond the metadata this tool handles, a file may carry: attachments embedded as whole files; annotations and comments with author names attached; form field values filled in earlier; embedded images that retain their own EXIF; embedded fonts, where an unusual subset can indicate the originating system; and JavaScript.

Then there is the structural issue. PDF supports incremental updates, where a change is appended to the end of the file and the original bytes stay put. A document edited that way holds its own history — earlier text, earlier metadata, content that was apparently deleted. Removing current metadata leaves all of that untouched. Exporting or printing to a fresh PDF flattens the history, which is why that is the standard advice before sharing anything sensitive.

Why Black Boxes Are Not Redaction

This has produced repeated public failures, in court filings and government releases alike. A black rectangle is a drawing instruction added to the page's content stream. The text underneath is a separate instruction and remains exactly where it was. Select the area and copy, or run any text extractor, and the supposedly redacted words come straight out.

True redaction removes the characters from the content stream and the corresponding region from any image, then rewrites the file. Software designed for it does this and marks the result. The verification step is simple and should be mandatory: open the finished document, select all, copy, paste into a plain text editor, and read what comes out.

A Worked Example You Can Reproduce

Take a PDF exported from a word processor and load it. The author field is likely your account name, the producer field names the exporting software and version, and the timestamps record when you wrote it. Download the sanitised copy and re-load it — the report comes back empty, which confirms the removal. Now open that cleaned copy and look at the first page: if your name is in the header, the document still identifies you, and no metadata tool can change that. Running select-all and paste into a text editor on both copies shows something else useful — identical extracted text, because metadata removal never touches content.

Frequently Asked Questions

Does this remove everything identifying from a PDF?
No. It targets the document information dictionary and XMP metadata packets, which is where author, title, producer, creator and timestamps live. It does not touch the page content itself, embedded fonts, embedded images with their own metadata, attachments, annotations, or any earlier revision kept by an incremental update. A PDF can carry identifying material in all of those.
What is an incremental update, and why does it matter?
PDF allows changes to be appended to the end of a file rather than rewritten, so the previous version remains in the bytes. A document edited that way can contain earlier text, earlier metadata, or content someone believed they had deleted. Removing the current metadata does not remove what an earlier revision holds.
Is a black rectangle over text a redaction?
No, and this is the most expensive mistake people make with PDFs. A drawn rectangle is a graphic placed above the text; the text is still in the content stream and comes straight back out with copy and paste or a text extractor. Real redaction removes the underlying content, which requires software built for it.
What does the producer field actually give away?
More than people expect. It names the software and often the exact version that wrote the file, which identifies the toolchain and sometimes the organisation — a specific licensed product, an internal pipeline, an operating system. Combined with timestamps it sketches how and when the document was made.
Is my PDF uploaded anywhere?
No. The file is read into memory in your browser and the sanitised copy is generated locally. Nothing is transmitted, and Clear removes the file from the page.
