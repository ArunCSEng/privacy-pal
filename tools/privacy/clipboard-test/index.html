⚠️ Operational Boundaries & Sandbox Notice

All clipboard inspections run strictly within local memory. Modern browsers restrict continuous background clipboard access to focused tabs or explicit user gesture triggers. This utility demonstrates how easily malicious sites can extract active buffer contents if permissions are inadvertently granted or if a user pastes into an arbitrary component. No captured clipboard strings or binary types leave your local machine. How Web Pages Intercept Clipboard Data

Browsers provide multiple vectors for web applications to interact with the system buffer:

  • Async Clipboard API (navigator.clipboard.readText() / read()): Requires an active browsing context and an explicit user permission grant in modern browsers. If granted, a background tab or scripts can silently read arbitrary clipboard text and images.
  • Event-Driven Paste Handlers (onpaste): Anytime a user presses paste inside a document or element, the site receives complete access to all associated DataTransfer types, including raw HTML, files, and rich metadata.
  • Legacy ExecCommand (document.execCommand('paste')): Largely deprecated in modern browsers due to uncontrolled sniffing vulnerabilities, but still supported in legacy webview runtimes.

Zero Network Egress Security Guarantee

Clipboard payloads frequently contain passwords, private keys, authentication tokens, and personal messages. BitDark processes all inspection logic entirely client-side using native browser APIs. No network telemetry, remote logging, or background requests are generated.
