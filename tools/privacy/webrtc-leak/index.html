How WebRTC Leaks Real IP Addresses

WebRTC (Web Real-Time Communication) allows direct peer-to-peer audio, video, and data communication within web browsers. To route packets through NATs, firewalls, and proxies, WebRTC uses the ICE framework alongside STUN (Session Traversal Utilities for NAT) servers:

  • Host Candidates: Enumerate your actual hardware network interfaces, including local IPv4 subnets (e.g., 192.168.x.x, 10.x.x.x) and link-local IPv6 addresses.
  • Server Reflexive (srflx) Candidates: Obtained via STUN queries. If you route web traffic through an ordinary browser proxy or certain non-firewalled VPN tunnels, WebRTC may bypass the tunnel and reveal your actual public WAN IP to the STUN reflector.
  • mDNS Masking: Modern browsers obscure local host candidates with ephemeral UUIDs (e.g., [uuid].local) to prevent device tracking and fingerprinting across internal subnets.

Mitigating WebRTC Exposure

To eliminate WebRTC leaks entirely, disable WebRTC in browsers that provide native toggles, install privacy-hardened extensions (such as uBlock Origin with the "Prevent WebRTC from leaking local IP addresses" setting enabled), or enforce system-wide firewall routing via a killswitch-equipped VPN client.
