⚠️ Operational Boundaries & Data Sanitization Disclaimer

Heuristic redaction cannot guarantee complete zero-disclosure privacy. This utility uses regex patterns to mask standard identifier formats (AWS credentials, OpenAI tokens, email addresses, IPv4/IPv6 blocks, and UUIDs). It cannot identify context-specific secrets, unique proprietary identifiers, custom variable names, or unstructured personally identifiable data embedded in conversation transcripts. Always perform a manual audit of all text before submitting queries to external LLM providers or untrusted APIs.

How Client-Side Redaction Protects AI Prompts

When you interact with cloud-hosted Large Language Models (LLMs), your prompt strings are typically stored in telemetry records, logged for abuse monitoring, or processed for downstream retraining. Sanitizing identifying parameters before transmission preserves prompt semantics while eliminating confidential telemetry leaks.

  • Deterministic Masking: Sensitive identifiers are replaced with typed synthetic tokens (e.g., [REDACTED_IPV4], [REDACTED_AWS_KEY]), maintaining prompt syntactic coherence.
  • Network Boundaries: Addresses matching standard IPv4 octets and RFC 4291 IPv6 hex blocks are masked to protect corporate infrastructure topology.
  • Credential Hygiene: Cloud provider keys (such as AWS AKIA prefixes, GitHub PATs, and OpenAI secret strings) are intercepted before external dispatch.

Zero Network Egress Guarantee

All token parsing and regex replacement executes inside your local browser thread via native JavaScript string routines. No text is transmitted to BitDark servers or external APIs.
