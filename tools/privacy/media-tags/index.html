⚠️ Limitations & Disclaimer

This reads metadata; it does not remove it. The tool reports what a container holds so you can decide what to do about it, and that decision needs a separate tool — usually a remuxer built on FFmpeg, which can rewrite the container without re-encoding the media. Two further limits: parsing covers the common container families and reports anything else as unrecognised rather than guessing, and a file can contain vendor-specific or deeply nested structures that are not surfaced here, so an empty report is weaker evidence than a populated one. What This Tool Does

Media files are containers: a structured wrapper around compressed audio and video streams, with room for metadata alongside. That metadata is where titles, artists, encoder names, creation timestamps, device models and — on phone recordings — GPS coordinates live. Drop a file in and the tool walks the container structure and reports what it finds, together with a SHA-256 digest identifying the exact file.

Photo metadata is now reasonably well known. Video metadata is not, and a phone video shared without thought frequently carries the same location leak that people have learned to strip from their photos.

How to Use the Tool

  1. Load a media file — an MP3, an MP4 or MOV from a phone, or a Matroska or WebM file. The phone recording is the one worth checking first.
  2. Look for location data before anything else. If coordinates are present, paste them into a map; seeing the result on a map is what makes the point.
  3. Read the device and software fields. Camera or phone model, encoder name and version, and the application that produced the file are all common, and together they describe your setup.
  4. Check the timestamps. Creation and modification times reveal when something was recorded and when it was last edited, which is often more than the person sharing it intended.
  5. Note the SHA-256 digest if you need to track this exact copy, for instance to confirm later that a file was not altered.
  6. Click Export Metadata JSON for a record, then Clear Analysis to remove the file from the page.

Three Families of Container

ID3 is the tagging scheme bolted onto MP3. Tags are frames with four-character identifiers, usually at the start of the file, holding title, artist, album, year, comments and embedded cover art. It is the oldest and simplest of the three, and the one most likely to carry leftovers from whatever software touched the file.

ISO base media underlies MP4, M4A and MOV. The file is a tree of boxes, each with a size and a four-character type. Metadata sits in boxes under the movie structure — user data, item lists, and the location box that phone cameras populate. Because the format is a tree, metadata can be nested several levels deep and is easy to overlook.

EBML underlies Matroska and WebM, and is best described as a binary tree with variable-length identifiers and sizes. Tags are elements that can be attached to the whole file or to a specific track or chapter, which makes it the most flexible of the three and the hardest to summarise briefly.

Why Video Location Data Matters

A geotagged photo of your home is one data point. A video is often longer, more revealing of the surroundings, and shared more casually — and the coordinates sit in the container just the same. Platforms that strip metadata on upload handle many cases, but files sent directly as attachments, through messaging apps that preserve originals, or via cloud links generally arrive intact.

The practical habit is the same as for photos: check before sharing, and turn off location tagging in the camera app for recordings you expect to send. Checking takes a few seconds; the alternative is discovering afterwards.

A Worked Example You Can Reproduce

Record a short video on a phone with location services enabled and load it here. Look for the coordinates, the device model and the creation timestamp, and map the coordinates. Then take a file that has been through a video platform and compare: typically the location is gone, the device model may remain, and an encoder string identifying the platform's own pipeline has appeared. Finally, note each file's SHA-256 digest and re-load one of them — the digest is identical, because it is a function of the bytes, and it would change entirely if a single metadata field were edited.

Frequently Asked Questions

Which container formats does it understand?
The three families that cover most files you will meet: ID3 tags as used in MP3, the ISO base media box structure behind MP4, M4A and MOV, and the EBML structure behind Matroska and WebM. FLAC is recognised as well. A container it does not know is reported as unrecognised rather than guessed at.
Why does a phone video contain GPS coordinates?
Because the recording app wrote them. In an MP4 or MOV the location is typically stored in a box within the movie metadata, alongside the creation time and often the device model. It is the same leak as a geotagged photo and it is less widely known, which makes it more likely to reach the internet unnoticed.
Does this tool remove the tags?
No. It reads and reports; it does not write files. Removing metadata from a container without re-encoding means rewriting the box or element structure, which is a job for a dedicated remuxing tool such as the ones built on FFmpeg. Knowing what is in the file is the step this tool handles.
What is the hash used for?
Identifying a specific file. A SHA-256 digest of the bytes lets you tell whether two copies are identical, or confirm that a file you re-downloaded matches the one you had. It describes the file, not its contents, and it changes the moment any byte changes — including a metadata edit that leaves the audio or video untouched.
Is my file uploaded anywhere?
No. The file is read into memory in your browser and parsed there. Nothing is transmitted, and Clear Analysis removes it from the page.
